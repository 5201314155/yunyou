## 一、定位与总原则

1. **主板论不变**：内核只提供插槽规格，一切能力=插在缝上的卡。Web 端插件与功能插件**同权**：同一 manifest、同一安装管线、同一生命周期，只是分发面不同（host 半=Rust 进程内/子进程，client 半=JS bundle 进浏览器）。
2. **一条安装管线**：广场安装与本地安装走同一内核管线（下载/校验→落位→manifest 校验→注册→生效），广场只是「提供安装源的前置发现层」，不产生第二条装载路径。
3. **官方机制照抄规格，不自创第三种注册模型**：槽位五基数×三 scope、共享单例表、configForms 修订写、错误边界，全部以 dsh 现行权威为蓝本（分册5 §二已裁六条）。
4. **fail-loud 全链**：manifest 违例、兼容性不符、校验失败=拒装或单插件 Failed 入表；market 插件失败只标该插件，不拖累整树（与 L1 bundled 整树 fail-loud 语义差异沿用 L2 §4.4）。

## 二、manifest `ui` 段的加法演进（相对分册5 的增量）

分册5 §三已裁 `[plugin.ui]` 七件（client/platform/inject/slots/config_forms/themes/locale）。本文在其上加法演进，**已裁字段一律不动**：

| 增量 | 内容 | 理由 |
| --- | --- | --- |
| ① `browser` 受限形态 | `[plugin.ui] browser = "client/browser.js"`，与 `client` 互斥；受限半经运行时注册面（`cordis_inspect` 等价物）声明，**不能 import/require 任何东西**，只能 `React.createElement`+`styles.insert(css)`+令牌自绘 | 官方 browser half 同型；给零构建依赖的轻插件一条路 |
| ② 槽位条目补 `scope` | `[[plugin.ui.slots]]` 每条增 `scope = "root"|"session-maybe"|"session"`（缺省 `session-maybe`）；补 `replace_risk = "none"|"shadows-shipped-ui"|"wraps-owner-content"`（声明期自评，装载期进启动审计） | 官方 CLIENT_NOTES 三值域；审计与文档目录都要用 |
| ③ `engines` 兼容段 | `[plugin]` 顶层增 `engines.yunyou = ">=0.4.0 <0.5"`；client bundle 增 `engines.client-shell`（对宿主壳版本） | 插件广场版本兼容的机器可读依据（§六） |
| ④ `signature` 段 | `[plugin.signature] algo = "ed25519" key_id = "…" sig = "base64"`，签 manifest 规范化字节的 sha256 | 广场可选信任升级（§六.4）；本地装无签名=允许，走信任分级 |
| ⑤ 单例依赖名钉死 | `inject` 白名单=平台单例表名（`react/jsx-runtime/react-dom`、cordis 等价物、store、ui-slots、ui-primitives、ui-dockkit、locale、configForms、theme）；声明表外名字=装载失败 | bundle externals 只解析单例表，声明与解析必须同源 |
| ⑥ icon 元数据 | `icon = "assets/icon.svg"`：包内相对路径、SVG/PNG/JPEG/WebP 白名单、≤256KB，超限即拒 | 官方 meta 校验同规格；广场卡片需要 |

**校验时机**：全部在装载期静态校验（槽位名对宿主槽位表、namespace 唯一、双主题齐、icon 格式、engines 语义化匹配）——与内核 manifest 九字段 validate 同口径 fail-loud。

## 三、宿主组图注入（entry 图与 boot 链）

宿主 webserver 独家撰写 entry 图，浏览器只消费。装载链五步（对表官方入口链，每步给 yunyou 形态）：

1. **组图**：host 半扫描已启用且带 `[plugin.ui]` 的插件，组合 WebBootGraph 写入页面：
   `window.__DSH_BOOT__ = { revision, entries: [{ id, bundle: "/plugins/<id>/client.js", row: "bare|sub", platform: "web", inject: [...] }] }`。
   安全不变量照抄：`global` 行渲染为 `globalThis[...]`、`<` 一律转义——**插件可控字符串逃不出 script 元素**；无有效图或畸形 entry=整页拒绝启动（fail-loud，不降级直跑）。
2. **入队**：页面 bootstrap 预置 `window.__ModuleLoader__ = { mode:"queue", load(reg){ pendingQueue.push(reg) } }`——插件 bundle 加载后调 `load({id, factory(require){…}})`，**只入队不执行**（懒）。
3. **建系统**：宿主在资源齐备后调 `__ModuleLoader__.create({ boot, staticModules })`；facade 缺失即抛错；create 之后 facade 再收 load 也抛错（防迟到脚本乱入）。
4. **激活审计**：完整 roster 到 settled+审计通过——web 必需名单 entry 未激活=拒绝启动；非必需未激活只告警；`replace_risk` 高于既定门槛的条目激活时打观测事件（§八）。
5. **挂载**：审计过后 hydrate boot DOM，**唯一一次** `ctx.slots.renderSlot('root', {})`。此后渲染权威在槽位树，不存在第二入口。

**bundle 端点**：`GET /plugins/<id>/client.js`（分册5 已裁，缓存粒度按插件、装载原子性按 entry，非官方 combo 同型——差异理由已注明在分册5 §四，不重复）。`browser` 受限半不走 bundle 端点：由宿主受限注册面直读脚本内容执行。

## 四、共享 React 单例与模块表

1. **单例表**：平台只持一组共享实体——`react`/`react-dom`/`jsx-runtime`、cordis 等价物（云悠 client 内核）、store、ui-slots、ui-primitives、ui-dockkit、locale、configForms、theme。插件 bundle 编译期以 externals 钉死这套名单，运行时 `require('react')` 拿到**与宿主同一 React 实例**——钩子、并发渲染、错误边界跨插件成立。
2. **越界即抛**：bundle 运行时 require 单例表外的名字直接抛错（§三步3 的模块解析器实现）；这是「inject 白名单=能力边界」的运行时执行点，不只靠 manifest 校验。
3. **包边界红线（成文）**：功能插件间只可 `import type` 共享声明，禁止运行时导入或转发另一功能插件的值；跨包行为走注入的 service，跨包 UI 走 slots。标准 client 插件**优先 require ui-primitives**（合法静态 owner），不引宿主具体组件包，严禁拷贝宿主 markup。
4. **构建契约（仓库外插件必读）**：`client` 产物=lazy-CJS factory 格式（单脚本、注册包名、`factory(require)`）；官方构建预设不随发行物分发，仓库外作者自建构建（SDK 将随包提供最小 esbuild 配置模板，`sdk/yunyou-plugin-sdk` 的 web 侧新增件，见 §十）。

## 五、安装/启停/配置/卸载生命周期（接内核）

内核侧已有：manifest 校验、注册即 effect（disposer 逆序）、epoch 代际门、取消信号贯穿。Web 插件生命周期 = 这些内核机制的对外投影：

| 阶段 | 动作 | 内核落点 | 失败语义 |
| --- | --- | --- | --- |
| 安装 | 解包→校验（签名/engines/icon/manifest）→落 `plugins/<类>/<id>/`（分类律）→登记 | `plugin install` 管线复用 | 任一步败=拒装，不留半成品 |
| 生效 | host 半注册（工具/命令/section）；client 半进组图 | epoch++，注入序列重算 | applied 才算生效；client 半需刷新页面拉新组图（报 `restart-required: client-graph`） |
| 启停 | 开关拨动=卸对应 fiber（逆序 dispose）+组图重写 | 工具/事件/section/槽位贡献全清 | 单插件 Failed 入表不拖他插件 |
| 配置 | `configForms` 修订写：`describe/operate`，写带 `expectedRevision`；宿主接受后广播 volatile-update→功能插件半重建注册 | 配置 schema 投影（契约④） | 过期写拒（409 语义），文件与 live 值都不变 |
| 卸载 | 槽位贡献清空、`<style data-plugin="<id>">` 移除、store 实例销毁、SDK 插件子进程收割（shutdown 帧+killpg+PDEATHSIG） | 热插拔标准：无残尸 | disposer 单点失败不阻断其余，残留记观测 |

**配置写唯一通道**：一切 client 侧配置写走 configForms 修订写，绕 revision 围栏的直写通道不存在（分册5 §七.8 维持）。密钥字段 `role:"secret"`：值只进凭据服务，表单不回显明文（契约⑤）。

## 六、插件广场（market）

### 6.1 远程索引

- `pluginMarket` 服务读用户配置的索引 URL 列表（volatile 配置字段，改动不重挂服务）：`listIndexes/search/entry/readEntryDetail` 四方法（照抄 frontend/packages/boot/plugin-market 规格）。
- 索引格式带校验器（`plugin-market-index` 等价物）：条目=名称/版本列表/分类/标签/兼容性声明/安装参数；非法条目整条剔除并报诊断，不静默。
- 详请页三步文档序（locale meta.detail→包 README→仓库 README），大小限额与缓存 TTL 沿用官方配置默认；CSP sandbox + nosniff 提供详情图片。
- **只读发现**：广场只做发现与元数据，安装一律转发给 `pluginManager.installBundle` 等价物——广场永不自带第二条安装路径（总原则2）。

### 6.2 版本兼容

- 匹配顺序：`engines.yunyou`（内核版本）→ `engines.client-shell`（壳版本）→ 平台声明（web/tui 有其一才可装）。任一不符=条目标 `incompatible`，UI 灰置并给原因文案，不可点装。
- 版本列表只读比已装新的版本；git 源以固定完整提交为更新目标，分支/标签 spec 不可更新（官方同律）。官方随行插件跟随内核版本不列更新。

### 6.3 本地安装同一管线

- `yunyou plugin add file:/path/to.tgz` 与广场安装收敛到同一 install 管线（§五.安装行）；差异仅在「源与信任」（本地文件可跳签名验证，走 §6.4 信任分级）与「无详情页」。
- 本地 tgz 装完同样进 manifest 校验、落位、组图、生效四步——**验收口径一致**：装→装载可见（/plugins）→真调用→卸载无残尸。

### 6.4 签名/校验与信任分级

| 级别 | 对象 | 校验 | UI 呈现 |
| --- | --- | --- | --- |
| T0 官方随行 | 内核附带 | 构建期校验 | 「官方」徽标 |
| T1 签名索引 | 配置的索引 | manifest `[plugin.signature]` 验签（ed25519，key_id 对已知发布键表）+ 完整性 sha256 | 「已签名」徽标；验签失败=整条拒 |
| T2 本地/无签名 | 本地 tgz、无签名索引 | 仅完整性+manifest 校验 | 安装前弹一次性确认（列能力边界：工具/网络/凭据声明），装后「未签名」标 |

- 密钥纪律：验证公钥表是宿主配置；**私钥永不出现在任何仓库与发行物**。签名只保证来源与完整性，不等于能力放行——能力边界仍由 manifest `inject` 白名单与 MVP 权限面（network=false、credentials=[] 恒禁至 ⑨ 开闸）管住。

## 七、权限与密钥边界

1. **能力三源**：manifest `inject` 白名单（client 服务面）+ `[plugin]` 权限字段（network/writable/credentials，MVP 口径见技能附录 C）+ TUI 端窄口（只 overlay 原语）。三者越界=装载失败或运行时抛错，不静默降级。
2. **密钥**：`role:"secret"` 值经凭据服务，永不进表单响应、日志、组图；client 半只见「凭据已就绪/未配置」布尔与 `with_access` 联动（分册5 §五.2：节常在、未配凭据呈引导态）。
3. **授权红线**：批准类动作只能留给宿主 approval service；插件面无「代用户批准」写入点，也不许做成 tool 让 Agent 自授权（安全律①）。
4. **数据界线**：插件组件不读他插件运行时值、不扫 DOM、不自建轮询；数据走 owner props/标准 hooks/inject 三层投影，组件**零 ctx**（架构红线成文）。

## 八、错误隔离与观测

1. **槽位级隔离**：entry boundary crash + `info.abdicate`（single/keyed 崩溃可退位）；崩溃的 hoc 层原位渲染 children 至本次挂载结束；crash 同步观察事件（对表 ui-slots renderer 行为，日志文案以 yunyou 实现为准）。
2. **进程级隔离**：SDK 插件子进程三层收割（§五卸载行）；单插件 Failed 不影响其余（market 语义）。
3. **观测三件**：①`/plugins` 页=静态清单+运行状态（含 Failed 与原因）；②槽位目录=编译时全表（key/kind/scope/replaceRisk）+实时树查询（`cordis_inspect what:"client"` 等价）；③load report=受限半注册失败在 `what:"temporary"` 等价面浮出。观测命令是开发工具（K-2 工具族延续），不进 agent 工具面。
4. **日志纪律**：会话日志禁 append 新 type（未知且非 ignorable 在 surface 层拒）；插件错误进宿主结构化日志（stderr=诊断通道纪律同样适用于 client 半的 console 投影）。

## 九、端到端验收清单

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| 1 | 装载链五步 | 组图注入→入队→create→审计→唯一一次 renderSlot('root')；组图畸形=整页拒启不降级 |
| 2 | 单例同源 | 插件 `require('react')` 与宿主同实例（钩子跨插件可用）；require 表外名=抛错 |
