# 命令体系设计（任务29·审二承接）

> 输入：《官方命令体系研究报告》（docs/架构/参照/官方命令体系研究报告.md）+ 业主三令（技能都进斜杠命令／Claude Code 两列面板形态／每次新开全新会话）。
> 写作纪律：自证设计理由；引用公开项目带归属（Gemini CLI 截图为业主提供参照，本设计不复制其实现）。
> 决策点以 **【决策点】** 标注，报 lead 批后生效。

## 一、三层边界（硬约束标注）

| 层 | 职责 | 落点 |
| --- | --- | --- |
| **主板面** | `commands` 服务缝：注册表/目录查询/分发（本设计 §二） | crates/yunyou（内核）+ crates/yunyou-tools 同级新 crate **yunyou-commands** |
| **插件面** | 各命令本体（含后续业务命令），插件 apply 内 register | 各组件 crate + manifest_ui Command 声明（§七） |
| **CLI 壳面** | 补全面板渲染 + 壳自有命令（/help /quit /new） | crates/yunyou-cli（§四/§五） |

**为何 commands 服务缝属于主板**：命令注册是宿主 UI 缝基础设施——任何 UI 适配器（CLI 补全面板/未来 App 面板）都要「列目录+分发」，这与 Context 服务注入、事件五分发同级（没有它每个 UI 各造一套注册表=重复造轮子）；它不承载任何业务语义（业务在插件命令的 handler 里），故属主板加强项而非业务功能。装配序列零硬编码：命令经 register 进表，装配代码只知道缝不知道清单。

**硬约束执行**：命令 handler 在宿主执行，参数与结果**不进模型请求**、不占工具白名单（工具契约 v1 的 schemas() 三元组不受影响）；register 返回 Disposer 随 fiber 卸载除名（与 ctx.effect 同语义）。

## 二、①命令注册缝（主板面）

- 服务 trait `CommandsService`（object-safe，经 ctx 服务注入）：
  - `register(def: CommandDefinition) -> Result<Disposer>`：同名已存在 → `Err(ServiceDuplicate)`，报错点名命令名（fail-loud 防静默遮蔽）；
  - `list() -> Vec<CommandDescriptor>`：name 排序稳定输出（提示词/面板可复现）；
  - `find(token: &str) -> Option<CommandDescriptor>`：解析入口（§三别名规则）。
- `CommandDefinition { name, aliases: Vec<String>, description, kind, handler }`；`CommandDescriptor` 为 list 的只读投影（面板消费，不含 handler）。
- `kind` 二分（**【决策点 D1】**，本设计关键裁决）：
  - **动作类**（Action）：handler 在宿主执行、结果文本上屏（/help /quit /clear 类）；
  - **展开类**（Expand）：handler **不执行副作用**，产出「输入框回填文本」（/技能名 类）——用户确认后作为普通用户消息发送，模型面内容由用户消息承载，命令面零进模型。技能命令归此类（§六），否则「技能进命令」与「命令不进模型」两约束相抵。
- 实现持 `RwLock<BTreeMap<String, RegisteredCommand>>`（顺序稳定）；注册即 effect（disposer 内 remove），HMR 卸载即除名；「重复 register 防御」：on_register 幂等哨兵——已注册同名再 register 直接 Err（不静默覆盖）。
- 作用域 shadow（per-agent 变体）：**一期只做全局层**，作用域层结构预留（层枚举占位不做），理由：一期单 agent 无 shadow 消费方，留结构不留实现（与 volatile 底座「预留位不占位」同纪律）。

## 三、②首批命令 + 别名机制

- `/help`（动作类）：文案**从注册表生成**（列 name+aliases+description），横幅「/help 看命令」从此名实相符——帮助文案禁硬编码（新增命令自动出现在帮助里）。
- `/quit`（动作类）：现 repl.rs:115 硬编码迁入注册表（handler 发退出信号）——作为「既有硬编码命令迁移」的示范件，迁移后 repl 循环只认注册表分发。
- `/new`（动作类）：§五会话隔离。
- **别名机制**：`aliases` 支持中文名（/帮助 /退出 /新建）；解析顺序=精确 name → aliases（别名不遮蔽任何精确名）；/help 两列展示主名+别名。
- 壳自有命令（/help /quit /new）在 CLI 壳装配时 register（壳面职责：退出/帮助/会话管理是壳的行为，不是插件业务）；业务命令一律插件面。

## 四、③命令补全面板（CLI 壳面·终端版自研）

- 形态（对齐业主 Claude Code 两列参照）：输入 `/` 触发 → 候选列表两列「`/命令名（别名）  描述」；继续输入=前缀过滤（name 与 aliases 都参与匹配）；`Tab` 循环补全、`Enter` 执行选中项；`Esc` 收起。
- 数据源=`commands.list()` 实时查询（无独立缓存——CLI 单进程直调，缓存属 Web 客户端跨进程场景的产物，终端版不需要）。
- **渲染范式对齐 D-UI-1**：候选列表每帧 `\r\e[K` 原位重绘——与思考活动行同机制（单行→多行候选列表的折行风险控制：候选行截断到终端宽度-2，列表高度封顶 8 行防滚动破坏回看）；非交互（管道）下补全面板整体静默（暂态判据同款）。
- 实现落点：crates/yunyou-cli/src/repl.rs 输入循环扩展（read_line 前的单行编辑态），不自研行编辑库（一期最小交互：字符过滤+Tab/Enter/Esc；方向键历史等留二期）。

## 五、④command/run+done 会话日志形态（**【决策点 D2】**按 lead 预裁给具体形态）

- **形态：零新增机制，复用既有 ignorable**。实证：yunyou-session/src/jsonl.rs:90-131 `load_all` 已区分 `Parsed::Event/UnknownType/Corrupt`——未知 type 行跳过+计数+`session/警告` eprintln 留痕；`SessionEvent` 枚举 tag=`type`（kebab-case）。**结论：不需要版本门**——tag 探测即版本门，旧读取器遇新类型自动走 UnknownType 跳过不炸（已实证的既有行为，非新承诺）。
- 新增两枚枚举变体（追加在五类之后，不改既有变体）：
  - `CommandRun { command_id: String, name: String, raw_input: String }`（tag=`command-run`）；
  - `CommandDone { command_id: String, kind: CommandOutcome, text: String }`（tag=`command-done`；`CommandOutcome::Success|Error`）。
- 配对：`command_id`=UUID（每次调用铸造）；run 先于 handler、done 后于结算（thrown/aborted 结算为 Error）——与既有 tool_call/tool_result 的配对纪律同构。
- 语义边界：命令事件是**纯日志配对**（回放/审计用），不进模型上下文组装（agent-loop 组 prompt 只消费 user/assistant/tool_*）；`raw_input` 一期恒记录（/help /quit /new 无敏感面；含敏感的命令属二期，届时加 record_input 开关——现在不做空开关）。

## 六、⑤会话隔离粒度 + REPL /new 语义

- **/new = 新会话文件**（对齐业主「每次全新会话」）：handler 执行链=①落定当前轮（close_block+turn_done）→②新会话 id+新 JsonlStore 文件（`<sessions>/<新id>.jsonl`）→③会话组件经 volatile/更新缝换 store（或一期简化：REPL 层持 store 句柄重建 SessionPlugin 配置并重启该 fiber）→④清屏+重印横幅。**一期裁决（简化版）**：会话组件重启走内核既有 update/reload 缝，不新造机制；若实现批发现 reload 缝不满足，回退方案=「/new 重启整个装配」（代价：毫秒级重装配，行为等价全新会话）——**【决策点 D3】**实现批按此优先序自证选择。
- 隔离粒度一期=每会话一 JSONL 文件（现状）；项目分组/代文件目录二期（现状单文件不阻 /new）。
- 旧会话不删（回查用 /resume 后置二期——一期 /new 单向新建，列表回放在会话文件层面已可 grep）。

## 七、⑥技能→命令注册映射

- 槽位：`.yunyou/skills/<文件名>.md`（宿主规格已定）——**文件名（去 .md）=命令名**，描述=首行 `# ` 标题或 frontmatter description（一期：首个一级标题）。
- 注册时机：REPL 装配时扫描槽位→逐个 register 为**展开类**命令（§二 D1）：handler 返回文件正文（展开文本）→补全面板选中后**回填输入框**（不自动发送）——用户可增删改后手动发送，模型面由用户消息承载。
- 守卫：文件名非法（不满足 `^[a-z][a-z0-9_-]*$`）→ 跳过+stderr 警告点名文件（不拒装其他技能）；与已注册命令同名 → register Err 已由缝 fail-loud，扫描器捕获后警告跳过。
- 中文名别名：技能 frontmatter 可写 `alias: 中文名`（一期可选，缺省无别名）。

## 八、⑦插件命令注册（manifest_ui Command 兑现）

- S8 已冻的 `UiEntry::Command { name }`（manifest_ui.rs:26-31，name 非空校验在位）兑现为：插件 apply 内 `ctx.commands.register(...)`——**声明面与实现面配对**：manifest 声明的 command.name 与 register 的 def.name 不一致 → 装载校验 **warn**（stderr 点名，不拒装——register 可晚于 manifest 校验发生，硬拒会误伤延迟注册）。
- 内置六能力命令（/compact /feedback 等后续批）与插件命令同构：各组件 crate apply 内 register，manifest 同步声明——装配序列零硬编码。
- 一期不做：market 级命令（多插件同名 shadow）、per-agent 作用域、/plugins 命令（S2 已裁诊断面后置）。
