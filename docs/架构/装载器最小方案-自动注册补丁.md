# 装载器最小方案：安装即自动注册（设计补丁）

> 提出人：云悠（agent 自评意见，业主拍板"安装应自动注册"）｜2026-11-14
> 性质：对《插件化改造方案》§2.2 两级表的一处时序修正建议，非推翻。

## 1. 问题

现状"安装"一个插件 = 写 crate + 改 `bundled.rs` 注册表 + 重编译。`[plugins]` 配置段已铺好 enable/auto_enable/config 面，用户看到配置面以为能装，实际装 = 改代码。**边界焊死了，门没装。**

后果：任务16"自举"验收若按现路径执行（改 bundled.rs → 编译成功），只是普通开发流程走一遍，不是自举。

## 2. 主张

把**装载器（manifest 发现层）**从 market 二期拆出，提前到地基（建议排 S2.5 或 S11，不阻塞 S2/S4）。

自动注册的硬约束先说清：Rust 无稳定 ABI，**进程内动态加载外部代码（dlopen）不可行，明确否决**。可行的"自动注册"只有两条路，且互不冲突：

| 层级 | 形态 | 解决什么 |
|---|---|---|
| **L1 发现层**（本期） | plugins/ 目录 + manifest 文件 + 与 bundled 实现自动匹配 | 安装体验：丢目录 → 重启生效 → 可开关，零 Rust 改动 |
| **L2 子进程骨架**（market 最小子集提前） | spawn + stdio JSON-RPC + 最小生命周期 | 真外部代码装载（官方既定路线 §2.2，无 ABI 问题） |

## 3. L1 设计（不动内核，只动装配层读清单的方式）

**目录约定**：`<yunyou-home>/plugins/<id>/manifest.toml`，每插件一目录。manifest 文件 = 既有 `PluginManifest` 的落盘投影（方案 §2.2 已预留"schemars 生成落盘"双形态，**零新格式**）。

**装载流程**（assemble.rs 启动期，纯增量）：
1. 扫描 `plugins/*/manifest.toml`，解析 + `validate_manifest` 同口径校验（格式非法 → 逐条报出，fail-loud 不静默）。
2. 发现条目按 id 匹配：
   - **命中 bundled 实现** → 与 BUNDLED_PLUGINS 条目合并，走既有 `enabled_of` / `check_slot_versions` / register 全链；manifest 文件可覆盖 auto_enable 缺省，`[plugins.<id>]` 配置段仍最高优先。
   - **未命中**（真外部包）→ L1 报"需 L2 子进程运行时，当前版本不支持"，明确诊断不静默降级。
3. `host_slot_support()` 不变；主板论不破——装配层仍是"知道清单接口"，只是清单从编译期常量扩为「编译期 ∪ 落盘发现」。D1"代码是真源"不破：bundled 实现仍在代码，manifest 文件是声明投影。

**验收（给任务16 自举立标尺）**：`<yunyou-home>/plugins/hello/manifest.toml`（id 命中某个演示 bundled 实现）→ 重启 → `/plugins` 可见可开关 → 拨下不留残尸 → **全程零 Rust 改动零重编译**。

## 4. L2 边界（本期不做，只冻结接口）

L1 的"未命中"诊断即 L2 的接入缝：发现层产出统一的 `DiscoveredPlugin { manifest_path, id }`，L2 届时把"bundled 匹配"分支旁的"未命中"分支换成子进程 Runner。tgz 安装/市场/签名仍留二期。

## 5. 开工拆卡（建议）

- K1：manifest.toml 落盘格式（schemars 生成 + 目录约定 + 解析器）｜yunyou-config
- K2：发现 + 匹配 + 校验接入 assemble（含 fail-loud 诊断与测试）｜yunyou-cli
- K3：`/plugins` 观测面标注发现来源（bundled/discovered）｜yunyou-cli
- K4（另立卡）：L2 子进程协议骨架，等 S4 工具契约闭环后动工

## 6. 风险

- manifest 文件与代码内 manifest() 漂移：复用 S1 既有校验器即可（同一 validate_manifest 口径，文件侧字段集为其子集）。
- 目录扫描的信任边界：L1 装的只是声明文件（不执行代码），无沙箱诉求；执行面全部仍在 bundled 代码或（二期）L2 隔离进程内。
