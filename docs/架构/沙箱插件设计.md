## 1. 威胁模型与四层阶梯（与崩溃隔离的互补边界）

**威胁定位**：任务27 崩溃隔离防「插件**写烂代码**搞死宿主」（panic/锁中毒，进程内）；本设计防「工具**造出的子进程**干坏事」（越界写/越权网络/提权逃逸，进程外）。两条线正交：沙箱不防崩溃（子进程崩了由 bash 工具既有收割路径兜底），崩溃隔离不防恶意（宿主活着的进程可以越权）。交汇点唯一：都要求「宿主自身不受损」——所以 **Landlock/seccomp 只上工具子进程，绝不上升宿主进程**（seccomp.rs:38-40 注释同语义：restrict on current thread so only the child inherits）。

**威胁面实证**（bash.rs 现状+任务17 D-17-1）：bash 起独立子进程，shell 重定向/tee/dd 天然绕过 path_guard（bash_guard/mod.rs:3-5 自证）；bash 图灵完备，文本门禁挡不住 eval/变量间接/编码绕过（mod.rs:34-40 已知盲区）；当前子进程**无任何内核级约束**。

| 层 | 机制 | 状态 | 只做前层做不了的事 |
| --- | --- | --- | --- |
| L0 | path_guard（文件类工具路径解析门禁） | 已有 | 守**进程内**文件工具的读写路径 |
| L1 | bash_guard 文本静态门禁（heredoc 状态机） | 已有（33 测试矩阵） | **快筛**：毫秒级零系统调用，执行前拦截四类直白越界写；错误带 hint 可教模型改路（§1 最弱够用） |
| L2 | workspace 授权快照（契约⑨ workspace 槽位） | 本设计接线 | **先授权后执行**：策略 Arc 快照单源贯穿 L2/L3（可写根单源防漂移）；cwd/root 解析与沙箱规则消费同一份集合 |
| L3 | 内核沙箱（landlock+seccomp，helper 进程） | 本设计主体 | **硬边界**：内核裁决，挡 L1 的一切绕过（拆词/eval/dd/rsync/ln -s/编码）；网络禁断 |
| L4 | 二期加固（bwrap 多后端/读遮盖/网络代理/审批链） | 二期 | ReadOnly 策略、凭据遮盖、cargo 拉依赖合法放行、拒绝后升级审批 |

**最弱够用原则**：每层只取「能拦住对应威胁的最弱机制」——L1 用文本扫描（便宜、可教）不动机器可读策略；L3 用内核白名单（强、不可绕）不做命令语义理解；L2 只是数据（快照），不引入新执行机制。**waterfall 缝一期不挂沙箱**：违规报告走既有 tool_result 文本通路（退出码+输出透传），不新增会话事件类型（会话日志禁 append 纪律）。

**为什么黑名单保留**（D12 重申）：沙箱是「执行期兜底」，不产生可教学的错误信息——模型 `echo x > /etc/passwd` 被内核 EACCES 后不知道路怎么改；L1 的 hint 指路面（write 工具/root 内路径）保留引导价值。代价是两套写根口径（L1 拒 /tmp 绝对路径、L3 放行 /tmp）：合法不一致——L1 是模型行为引导层（更严），L3 是安全下限（更松），模型永远先撞 L1，不存在「沙箱放行但体验矛盾」。

## 2. 插件形态（契约面＝主板规格，执行面＝卡）

```
主板（规格层，落 yunyou-tools）：
  contract.rs   ToolExec.workspace: Option<WorkspaceContext>   ← 既有槽位，本设计充实
                WorkspaceContext { policy: Arc<WorkspacePolicy> }
  sandbox.rs    WorkspacePolicy v1（字段冻结见 §3.1）
                trait SandboxEnforcer { fn prepare(&self, &WorkspacePolicy) -> io::Result<PreparedSandbox>; }
                PreparedSandbox（helper spawn 参数集：策略 JSON/命令 cwd/argv 分隔语义）
卡（执行面，新 crate yunyou-sandbox，bundled）：
  manifest      contracts=["sandbox.v1"]，provides=[dyn SandboxEnforcer]，level=bundled
  config        [sandbox] enabled: bool = true（volatile 热调）；writable_tmp: bool = true
                network_denied: bool = true（改配置重启生效，不热调——运行中放开网络=安全面突变）
  setup         构建 LandlockEnforcer → ctx.provide
消费方：tools 插件 setup 时 ctx.get::<dyn SandboxEnforcer>()（可选消费）
  ├─ Some(enforcer) → BashTool 携 enforcer，spawn 时走 helper 链（§3.4）
  └─ None（沙箱被禁用/未装载）→ BashTool 直跑 + warn 日志 + 结果 meta 标注 unsandboxed（降级显式告警）
```

三个形态裁决：

1. **enforcer 是可选消费，不进 ToolsPlugin.inject**：inject 声明=「依赖消失即卸载」的 epoch 语义——若声明强依赖，用户禁用沙箱插件会连带瘫痪整个工具面（tools 永卡等待），违反「禁用的是沙箱不是工具」。可选 get+降级告警把选择权留给策略而非装配事故。
2. **依赖方向单向**：trait 与策略类型落 tools 契约 crate，实现落 yunyou-sandbox（插件依赖契约 crate，反向禁止）——与《超时重试插件设计》RetryPolicyProvider 落 yunyou-llm 同一归属规则；内核（yunyou crate）零改动，装配序列零改动（§任务书红线「禁硬编码进装配」）。
3. **文件类工具不接沙箱**：fs_tools/search 在宿主进程内直接 IO，L0 已守；宿主进程不设限（§1）。沙箱的服务对象=**进程类工具**（一期唯一 bash；后续 procmgr/团队 worker 复用同一 enforcer）。

### 2.1 模型告知段（lead 修正案④，2026-11-14；经契约③ systemPrompt section 缝）

**机制**：yunyou-sandbox 插件 setup 时经契约③ section 缝 `register_section(Section{name:"sandbox", order, text})` 贡献一段系统提示，disposer 随插件卸载注销（热插拔不留残尸）。**诚实律（本段硬约束）**：告知面必须与执行面同源——段仅在沙箱实际生效（enabled=true 且 enforcer 在位）时注册；`[sandbox] enabled=false` 或 enforcer 缺失时**不注册**（模型面绝不允许描述与真实执行不符的行为，宁缺勿谎）。partial-enforcement 场景亦自洽：NotEnforced 走 §3.6 fail-closed 拒执行，不存在「段已注册、内核未强制」的中间态。槽位登记随 S4 段位表落地对齐（建议紧邻工具使用指导段）。文案草案（实现批可微调措辞，不得变更事实面）：

> ## 沙箱执行环境
> 你的 bash 命令在系统沙箱中执行。这是内核级硬边界，不是可协商的规则：
> - **可写范围**：仅当前工作区目录。工作区之外的任何写入都会被拒绝——需要写工作区之外的位置时，停下来向用户说明诉求（目标路径与原因），由用户决定调整工作区或自行操作，不要尝试绕过。
> - **无网络**：命令不能访问网络。`git clone`、`cargo add`、`pip install` 等需要下载的操作会失败，这是预期行为，不会因重试而改变；优先使用本地已有的依赖与仓库，确需联网时停下来告知用户。
> - **权限拒绝≠故障**：看到 `Permission denied`、`Operation not permitted` 或命令异常退出时，先判断是否触碰了上述边界；若是边界拒绝，不要换写法反复重试（换 shell 语法、编码、间接调用都不会成功），直接改道或说明原因。
> - 工作区内的常规开发动作（读写文件、构建、测试）不受影响。

四条行为学依据（为什么是这四句、不是更多）：①写边界+改道指引——越界后的**事后**指路已由 L1 错误 hint 承担，本段做事前告知，两层互补；②网络禁断+替代动作——cargo 拉依赖失败必须被模型解读为「预期」而非「环境坏了」，否则进入重试循环（340s 事故同类模式的事前免疫）；③「拒绝≠故障」直接堵「换写法绕过」的试错路径——试错本身就是越界尝试的放大器，与 §8 绕过用例组对应；④末句收尾防过度保守——把沙箱框定为「正常开发不受影响」，什么都不敢跑是另一种失败模式。**不写** landlock/seccomp 等实现名词（模型按行为面决策，实现名是噪音）；**不写**「可自行测试边界」类挑衅句式；**不提**临时目录可写（bash_guard 仍拦 /tmp 绝对路径重定向，写了反而制造模型面与门禁面的表面矛盾——临时目录是内部机械面，模型无感知需求）。

**验收追加（落 §8）**：告知面三态断言——生效含段/降级无段/卸载段消失。

## 3. Linux 落地（优先）

### 3.1 策略对象 v1 与可写根模型（root 内 workspace 读写白名单）

```rust
/// 策略快照（v1 冻结面；构造一次，Arc 贯穿 L2/L3，防两处解析漂移）
pub struct WorkspacePolicy {
    /// 可写根集合（全部 canonicalize 后绝对路径；含 workspace root）
    pub writable_roots: Vec<PathBuf>,
    /// 出网许可；v1 恒 false（枚举留位：二期 NetworkMode::{Denied, Proxy}）
    pub network_access: bool,
    /// 策略语义版本（契约冻结位；helper 校验不识别即拒）
    pub policy_version: u32,   // v1 = 1
}
```

- **可写根构造**（yunyou-sandbox 插件侧）：`[workspace root, /dev/null, /tmp?, TMPDIR?]`；`writable_tmp=false` 时去掉 /tmp/TMPDIR。/tmp/TMPDIR 默认并入的硬理由：bash 的 pwd 捕获临时文件落在 `std::env::temp_dir()`（bash.rs:166-174 实测），不入集合则统一目录视图当场失效；编译器/链接器临时文件同理。exclude 语义二期需要再拆细（现单开关够用，Codex 的 exclude_slash_tmp/exclude_tmpdir_env_var 两键是场景驱动的过度预造）。
- **读=全盘**（ruleset 只 add read "/"）：工具链合法性是硬约束——cargo/rustc/bash 读自身与系统库、/proc、/etc/ssl；读白名单=维护「工具链根清单」且路径漂移即坏，误伤代价高于收益。TS 版官方 Landlock 档同样 `readOnly: ['/']`（profiles.ts:26-31 实测）。**越界读残余风险明示**：`cat ~/.ssh/id_rsa`、`cat ~/.dsh/.credentials.yaml` 一期可读——已立票「bash 越界读归 sandboxPolicy 排期」（683cde0），归二期：Landlock 纯 allow-list **表达不了读拒名单**（只能白名单层级，不能「全盘读减若干黑点」），读遮盖的正确机制=bwrap 在敏感路径上盖 tmpfs（TS bwrap `--tmpfs /tmp` 同族思路），二期随 bwrap 后端一并做。
- **先授权后执行**（契约⑨另一半「路径映射原子校验」的最小形态）：策略在 spawn 前由 enforcer 构建成不可变 PreparedSandbox，执行期无二次路径解析——cwd/base 与规则根同源于一份 canonicalize 结果。

### 3.2 Landlock 规则模型（写限制）

规则构建（预编译在 parent，应用在 helper）：
`Ruleset::default().set_compatibility(BestEffort).handle_access(AccessFs::from_all(ABI::V5)).create()` → `path_beneath_rules(["/"], read)` ＋ `path_beneath_rules(writable_roots, read_write)` ＋ `set_no_new_privs(true)` → `restrict_self()`。**NotEnforced 检测=fail-closed 硬门**：内核无 Landlock（<5.13）时 crate 静默不强制，`RulesetStatus::NotEnforced` 必须显式报错拒执行（本机内核 7.1.2 实测支持，但发布面不能赌内核版本）。规则按**目录层级**绑定：workspace 内后续新建文件自动受控，无需重挂；workspace root 每次 spawn 重新 canonicalize（防目录被 mv 后规则漂移）。

选型理由（自证）：Landlock 是内核原生 LSM，无外部二进制、无 root、无命名空间权限要求，规则语义（层级白名单）与「workspace 写白名单」一一对应；代价=表达力限于 allow-list（故读限制归二期，§3.1）。

### 3.3 seccomp 网络禁断（一段静态 BPF，非代理）

deny-list（**比 allow-list 抗 libc 演进**：白名单要枚举全部合法 syscall，一漏即坏；黑名单只列网络面，其余全放行）：

| 类别 | syscall | 理由 |
| --- | --- | --- |
| 网络主面 | connect/accept/accept4/bind/listen/shutdown/sendto/sendmmsg/recvmmsg/getpeername/getsockname/getsockopt/setsockopt | 网络会话全族；`recvfrom` 放行（socketpair 子进程管理合法面，Codex 同判） |
| socket 创建 | socket/socketpair：**仅放行 AF_UNIX 域**（参数条件规则） | `cargo`/`git` 子进程管理靠 unix socketpair；INET 全断=网络禁断的执行点 |
| 逃逸旁路 | io_uring_setup/enter/register | io_uring 可绕过 socket(2) 直接建 socket，不堵=过滤器白装 |
| 宿主侵害 | ptrace/process_vm_readv/process_vm_writev | 防沙箱子进程反向篡改/读取同用户宿主进程内存（凭据在宿主侧） |

前置：`prctl(PR_SET_NO_NEW_PRIVS, 1)`（seccomp 安装的内核要求，兼防 setuid 提权）。过滤器由 seccompiler 预编译成 BPF 程序，helper 内 `apply_filter` 一次安装。上述名单吸收自 Codex Restricted 模式实测段（linux-sandbox/src/seccomp.rs:90-260，Apache-2.0；选型判断为本方：deny-list 论证+ptrace 面扩充）。**Landlock 的 AccessNet（connect/bind 级）不用**：表达力弱于 seccomp 全族禁断（管不住 accept/socket 族），双机制只取强者。

### 3.4 helper 进程形态（三案对比裁决）

| 案 | 形态 | 取舍 |
| --- | --- | --- |
| A. pre_exec in-process | parent 的 tokio Command pre_exec 闭包内 fork 后应用 landlock+seccomp 再 exec | 零新进程，但 fork-from-multithreaded 的 async-signal-safe 灰区实存（crate 内部分配不保证安全；std 有 pre_exec 时弃 posix_spawn 走 fork+exec，风险收敛但非零），unsafe 面摊在工具热路径 |
| B. sibling 二进制（Codex 形态） | 独立 `codex-linux-sandbox` bin+install-context 查找（linux_run_main.rs:56-95 CLI 面） | fork 灰区归零；代价=多构建产物+查找逻辑+「helper 丢失」失败面 |
| **C. arg0 自唤起（采纳）** | parent spawn **current_exe 绝对路径**＋argv[0] 哨兵名 `yunyou-sandbox`＋`--policy-json`＋`--`＋用户命令；main 检测哨兵走沙箱分支 | 单二进制分发不变（相对 B 消灭查找面）；helper 是 fresh exec 的单线程进程，apply 期零并发、fork 灰区归零（相对 A）；代价=main.rs 一条分支+哨兵参数校验（不识别即按普通命令退出） |

C 案要点：①parent 侧零 unsafe；②策略经 argv JSON 传递（含可写根绝对路径，无敏感数据），`--` 分隔防用户命令参数被 helper 误解析（Codex landlock.rs:64-66 同构做法）；③helper **exec 换映像**：应用完 landlock+seccomp 即 execvp 用户命令，PID 不变——parent wait 到的就是用户命令本体，退出码/信号天然透传，无需 Codex bwrap 形态的信号转发层；④**pre-main 加固三件套吸收**（process-hardening/src/lib.rs:44-61，Apache-2.0）：`PR_SET_DUMPABLE=0`（防同用户 ptrace 沙箱子进程）＋`RLIMIT_CORE=0`（禁 core dump 泄内存）＋清洗 `LD_*` 环境变量（防库注入）——helper main 开头同步三行，不引 ctor 依赖。

### 3.5 子进程继承语义（论证，写进 rustdoc）

- **Landlock**：restrict_self 后**恒继承**——fork/exec/孙进程全受限，无任何用户态撤销路径（内核无对应 syscall）；规则绑定 inode 层级，子进程在 workspace 内建目录/文件照常（新文件在受控层级内）。
- **seccomp**：过滤器随 execve 存续（NO_NEW_PRIVS 已设时内核强制保留）；`sudo`/`su` 的 setuid 位在 NNP 下**不生效**→提权即失败，`bash /dev/tcp/host/port` 建网被 socket 族 deny 拦截，`unshare` 反用法被「无 CAP_SYS_ADMIN 的普通用户+已有过滤器」组合封死。
- **宿主不受限**：helper 只对「即将 exec 用户命令的进程」设限；yunyou 主进程/插件进程/会话落盘/LLM 中转连接零波及。这是「防恶意不自杀」的边界，也是 §1 互补边界的执行面落点。
- **AF_UNIX 残余面明示**：本机 unix socket 可连（cargo 合法面）→ docker.sock 类高危 socket 依赖其文件权限兜底（通常 root 属主 660，非 root 连不上）；记录在风险表，二期 managed-proxy 收口。

### 3.6 失败面与降级（全部显式，无静默）

| 场景 | 行为 |
| --- | --- |
| enforcer 缺失（插件禁用/未装载） | bash 直跑＋warn 日志＋结果 meta `sandboxed:false`（降级显式告警） |
| helper 应用失败（NotEnforced/规则构建错） | helper 以专用退出码退出，parent 归一 `tool/sandbox-failed` 错误（fail-closed，**不回退裸跑**） |
| current_exe 不可得/哨兵分支异常 | 同上归一；绝不静默降级（降级只走 enabled 开关这一条受控路） |
| 用户命令被内核拒绝 | EACCES/EPERM/SIGSYS 原样透传（退出码+输出），模型与用户可见真实原因 |

## 4. macOS Seatbelt（仅记录思路，不实现）

形态：`sandbox-exec -p <SBPL>`（进程级 profile，无内核部署面）。TS 版官方渲染规律（profiles.ts:38-47 实测）：`(allow default)` 起底＋`(deny file-write*)` 收写＋`(allow file-write* (literal "/dev/null"))`＋`(allow file-write* (subpath <可写根>))`——与 Linux Landlock 同一策略对象渲染成不同后端文本，验证 L2 快照单源跨平台成立。Codex 补充两点纪律（sandboxing/src/seatbelt.rs:59-60）：`sandbox-exec` 只认 `/usr/bin` 绝对路径（防 PATH 注入假沙箱）；Apple 已弃用该接口但仍可用，发布时需接受告警。网络禁断走 `(deny network*)`。**实现时机**：macOS 发布批立项时，归二期 P1-11b。

## 7. 一期/二期切分

### 7.1 一期（P1-11a，受约束批 S11：策略对象+单后端最小沙箱）

范围：①契约面三件（WorkspacePolicy v1/WorkspaceContext 充实/SandboxEnforcer trait，落 yunyou-tools）②yunyou-sandbox 插件（Landlock+seccomp+helper 分支+加固三件套）③bash 接线（门禁→cwd 解析→enforcer→helper spawn，tokio::process 换目标不动取消/进程组/输出既有契约）④降级与失败面（§3.6）⑤混沌用例矩阵（§8）⑥依赖报批（§6，**已批**）⑦模型告知段经契约③ section 缝（§2.1）。

**网络禁断纳入一期的论证**（推翻《超时重试插件设计》§6「一期不做网络隔离」的范围控制；**lead 已裁：采纳进一期**，2026-11-14 13:2x；workflow 破环面按 §7.2 明示）：①威胁模型变了——本设计防恶意（任务书），无网络禁断的沙箱=「锁了门开着窗」：越界写收益有限（白名单外不可写），但 curl 外传源码/凭据、反向 shell 通道全开；②**零合法破坏面**：LLM 中转在宿主侧，工具子进程无任何合法网络需求——「没有需求面」恰是禁断的论据而非障碍；③实现=一段静态 BPF（§3.3），不引代理/netns，成本≈Landlock 本体的一半；④契约一次定型：v1 就冻结 network_access 字段，避免二期加网络位时 WorkspaceContext 二次演进。原裁决的范围控制理由（LLM 中转在宿主侧）经查证反而支持禁断。

## 8. 验收口径（混沌用例矩阵；S11 验收=全表绿）

**越界写（预期拦截层标注）**：

| 用例 | 预期 |
| --- | --- |
| `echo x > /etc/y`、`>> /etc/y`、`2> /etc/y` | L1 拦（hint 指路）；L3 兜底 EACCES |
| `te'e' /etc/y`（拆词绕过 L1 已知盲区）、`eval '$CMD'`、`dd of=/etc/y`、`rsync ... /etc/y`、`ln -s /etc/y link; echo > link`、`$( )` 内重定向 | **L1 漏、L3 拦**（沙箱价值的直接证据组）；符号链接跟随解析至 /etc 层级被拒 |
| heredoc 体内越界文本、未终止 heredoc | L1 fail-closed 拦（既有矩阵回归） |
| workspace 内正常写（子目录/新文件/`>>` 追加） | 全通过（不回归） |
| `pwd` 捕获（cd 后退出码回写） | 通过（/tmp+TMPDIR 可写根兼容 CaptureFile） |

**越权网络**：`curl http://example.com`、`python3 -c socket`、`bash /dev/tcp/1.2.3.4/80`、`git clone https://...`、`ping`（raw socket 无 cap）、`nc -l`（bind/listen deny）→ 全部被 L3 拒（EPERM/网络错误透出）；`cargo build`（已下载依赖，本地编译+socketpair）→ **通过**。

**绕过尝试**：dlopen 本机库（无网络下载面，外传被网络禁断卡）→ 写/读仍受限；setuid 提权（NNP）→ 失败；ptrace 宿主进程（seccomp+dumpable=0）→ 失败；io_uring 建 socket → 失败；内核漏洞类（0-day）→ **超出威胁模型**，明示不承诺。

**降级与失败**：`[sandbox] enabled=false` → 直跑+warn+meta 标注；模拟内核无 Landlock（规则构建注入桩）→ `tool/sandbox-failed` 拒执行不裸跑；helper 不识别 policy_version → 拒执行。**告知面三态**（§2.1）：enabled=true 且 enforcer 在位 → compose 输出含「沙箱执行环境」段；enabled=false → 不含（字符串级断言）；插件卸载 → 段随 disposer 消失（无残尸）。

**回归**：path_guard/bash_guard 既有矩阵全绿；tools 33 测试+workspace 全量测试绿；取消/进程组/输出截断契约不回归（helper 形态下 child.wait/kill 路径复验）。
