## 一、缝位与范围（先复述边界，禁脑补）

## 二、装载形态三路对比裁决

### 2.1 三路对比表

| 维度 | 案A 进程外子进程+stdio JSON-RPC | 案B 动态库 dylib | 案C 嵌入式脚本（Rhai/Lua/WASM） |
| --- | --- | --- | --- |
| ABI 稳定性 | 协议=JSON 契约，版本化握手，天然稳定 | **Rust 无稳定 ABI**：符号重整化随编译器漂移、结构体布局无保证、跨 crate 版本即碎 | 脚本语言自身稳定；但「脚本↔宿主」绑定层=事实 ABI，随内核 API 面增长逐处维护 |
| 崩溃半径 | **OS 进程边界=插件死≠主板死**（业主令「防插件搞溃程序」直接命中） | 同进程：panic 穿透/中毒锁击穿无辜者（崩溃隔离设计 §1.2 三凶点实证）——隔离机制全部失效 | 同进程：Rhai/Lua panic 与死循环阻塞内核任务；WASM 可拦但宿主边界=另一套 RPC 同构物 |
| 语言生态面 | **任意语言可实现协议端**（终稿 K-13 校正版论据：语言无关最大化作者面） | 仅 Rust，且须与宿主同版本编译 | Rhai/Lua 小众；WASM 工具链重、宿主接口暴露面难收敛 |
| 能力面覆盖 | 工具/命令/提示段经协议词汇逐面开放，节奏可控 | trait 直调全覆盖 | 每面都要写绑定层 |
| 沙箱衔接 | Landlock+seccomp+NNP 套在插件进程上（现成 helper 机制，见 §4.1） | dylib 代码在主板进程内跑，**内核沙箱无法只作用于库**（Landlock 进程级） | 脚本解释器内可做软隔离但非内核级；WASM 线性内存强但宿主函数=逃逸面 |
| 卸载 | kill 进程组+注册面 disposer 注销，干净 | dlclose 不安全：static 析构/thread-local/tokio 全局态均不可回收（装载器最小方案 §2 已否决 dlopen） | 可卸但绑定残留易留尸 |
| 安装体验 | 丢目录+manifest，零编译 | 需预编译产物且与宿主版本严格配对 | 丢脚本，但表达力受限 |
| 与既有裁决 | **=分册4 §2/蓝图终稿 §三已裁形态，本席复核证据后维持** | 终稿已裁「cdylib 永久关闭」，本席复核维持 | 终稿已裁「WASM 二期观望，缝已预留」；Rhai/Lua 无既有裁决但无必要另立 |

### 2.2 裁决

**采纳案A**。三条硬理由：①ABI——Rust 无稳定 ABI 是语言事实，dylib 路线的三类碎裂（符号/布局/卸载）无一可在我方工期内核解，且 dylib 崩溃半径=主板进程，与崩溃隔离 v1 已建立的「插件崩≠主板崩」防线（S-ISO-2/3/4 已落库，5fe7a/730e157）方向相反；②沙箱——插件进程是唯一能完整套用 Landlock 写白名单+seccomp 网络禁断+NNP 的形态（sandbox crate 现成衔接，§4.1）；③生态——官方 dsh 插件是进程内 JS 组件（npm 包+cordis，K3 §一证据），我方**不走「直接跑官方插件」**（终稿 K-13 校正注记），机制同构对标已足够，子进程协议换来的是任意语言作者面。
案C 处置：WASM 维持「二期观望、缝已预留」（终稿 §三原文）——本案A 的协议边界（版本化+封闭枚举+能力协商）与 WASM 宿主边界同构，届时换传输层不换词汇；Rhai/Lua **不立项**（绑定层成本+WASM 已占同生态位）。

### 2.3 代价表（诚实面）

| 代价项 | 量级 | 状态 |
| --- | --- | --- |
| 进程冷启动+握手 | 毫秒~几十毫秒级（spawn+exec+JSON 往返×2） | **未证实**——终稿开放项1 明挂「B5 基准 P99<2ms 待基准」；本设计把 B5 简化版（冷启动+单次往返两个数字）列入 L2-MVP 验收，不再后移 |
| 每次工具调用 | 一跳 RPC 往返+JSON 序列化 | 同上；高频核心工具不走 L2（分流原则见 §8 风险1） |
| 常驻内存 | 每启用插件一进程 | 分册4 B8 预算「<16KiB/插件」是对进程内 fiber 的口径，进程外不可比——如实改为「每插件进程 RSS 单列观测，不套 B8」 |
| 协议维护 | 封闭枚举+版本化演进纪律 | 一次立律，长期摊薄（与 ipc-types 同款纪律，§3.3） |
| 调试面 | 跨进程排障 | stderr 前缀透传+状态表 failed 行+诊断人话（§5） |

## 三、契约面（manifest v2 + 协议词汇）

### 3.1 manifest.toml v2 字段（加法演进，serde default 律）

基座=ManifestFile 现有八字段（id/version/level/contracts/provides/inject/ui/auto_enable）**零改动**，新增：

| 字段 | 类型 | 语义 | 校验 |
| --- | --- | --- | --- |
| `format` | 整数，缺省 1 | 落盘格式版本；**v2 必填 =2** | 未知值拒装报「不支持的格式版本」（对齐 GatewayIpcFrame 未知 type 拒绝语义） |
| `[runtime]` 段 | 表，v2 market 必填 | 装载形态声明 | level="market" 而 runtime 缺失 → 拒装 fail-loud |
| `runtime.type` | 字符串 | 当前唯一合法值 `"subprocess"` | 其他值拒装（WASM 未来经此处演进，不动结构） |
| `runtime.entry` | 字符串数组 | 插件入口 argv（如 `["python3","main.py"]`），路径项相对**插件目录**解析 | 禁绝对路径、禁 `..` 上跳（K3 B-5「icon 只能是包内相对文件」同构）；可执行文件必须落在插件目录内 |
| `runtime.request_timeout_ms` | 整数，缺省 30000 | 单次工具调用超时；超时=软失败计 fail-loud | >0 |
| `[permissions]` 段 | 表，缺省全最小 | 权限声明（§4） | 未声明=无权限，无静默放宽 |
| `permissions.writable` | 字符串数组，缺省 `["$SELF"]` | Landlock 写白名单附加根；`$SELF`=插件目录 | 只接受 `$SELF`/绝对路径；非插件目录内路径逐条人话警告不阻断（warn 不 fail，终稿「授权类动作只能留给用户」——用户写进配置即用户授权） |
| `permissions.credentials` | 字符串数组，缺省空 | 声明要用的凭据名（L2.1 生效，MVP 词汇未开=声明了也拒装报「凭据面未开放」） | 名单即授权边界 |
| `permissions.network` | 布尔，缺省 false | 网络放行开关 | L2-MVP **恒拒 true**（协议词汇无网络面承诺，先关闸）；L2.1 起按声明放行 |

**兼容律（bundled 投影不破）**：命中 bundled 的 manifest.toml 走 L1 既有分支零改动（投影+漂移警告语义原样）；`format` 字段在 L1 命中分支=忽略（bundled 声明投影不需要它，加字段即加法演进、serde default 兼容，tools v1.1 hint 先例）。market 分支 enable 判定=两级：`[plugins.<id>] enable` > 文件 auto_enable（缺省 true）——无代码级第三级，与 L1 三级链的差异有据（market 无代码内 manifest），如实写明非破坏。

**contracts 消费面校验（market 分支新增，装配层做，不动内核）**：market 插件 `contracts` 仍必过 `check_slot_versions`（宿主支持集）；另加**开放面白名单**——L2-MVP 允许集=仅 `tools.v1`（进程外插件可消费的宿主插槽），声明白名单外插槽（如 session.v1）→ 拒装报「插槽 session 未对进程外插件开放」。provides 对 market=纯声明（观测展示），不进宿主服务表（进程外无 trait object 可 provide）——这是能力面边界不是缺陷，人话写进诊断。

### 3.2 协议词汇（L2-MVP 最小封闭集）

新封闭枚举（`#[serde(tag="type", rename_all="snake_case")]`），JSON Lines 帧格式（`\n` 分隔），帧纪律全部对齐 `yunyou-ipc-types` 演进律：**未知 type 标签=解码拒绝（暴露面铁律的类型化执行，ipc-types lib.rs:42-44 同款）；新增消息类型=本设计修订走评审线一，禁私加；握手版本比对，不兼容=hello_err fail-loud（PROTOCOL_VERSION 模式同源）**。

| 消息 | 方向 | 载荷要点 |
| --- | --- | --- |
| `hello` | 宿主→插件 | protocol_version + capabilities（MVP=空集占位，加法演进钩子） |
| `hello_ok` / `hello_err` | 插件→宿主 | 版本回显 / 中文拒绝原因（版本不符→装配 Failed，不静默降级） |
| `tools_list` / `tools_list_ok` | 宿主↔插件 | 插件上报工具清单：name/description/parameters(JSON Schema)/output_schema?/timeout_ms?/is_concurrency_safe? |
| `tool_invoke` | 宿主→插件 | invoke_id + name + args（JSON） |
| `tool_result` | 插件→宿主 | invoke_id + outcome（ok(value) \| err{code,message,hint}）——**tools.v1 ToolOutcome/ToolError 三元组投影，错误码语义同源**；hint 加法演进律随 tools.v1 |
| `shutdown` | 宿主→插件 | 卸载/停用通知；插件回执后宿主 kill 兜底（不回执也杀，不悬挂） |

**词汇演进预留（L2.1 才开闸，设计期只占位不实现）**：`tools_changed`（热更新清单）/`cancel`（AbortSignal 贯穿——MVP 靠 request_timeout 硬超时，取消语义「等静止不 abandon」在 L2.1 与 tools.v1 对齐）/`credentials_get`（§4.2）。

### 3.3 协议落点与 crate 纪律

**新独立 crate `yunyou-plugin-proto`**（协议类型单源，双端共用防漂移），**不复用 GatewayIpcFrame**：①ipc-types 是「网关↔agent」域单源，其封闭枚举演进律绑定网关落地方案修订——混入插件消息会让两个域的暴露面互相牵连（网关改帧要过插件评审，反向亦然）；②消费者不同（gateway/ipc-server vs 插件 Runner）；③对齐=复用其**纪律**（封闭枚举+tag type+JSON Lines+版本握手+未知拒绝）而非复用其类型。crate 定位=无层属性零业务依赖（依赖上界 serde/schemars+yunyou-util，与 ipc-types 同款禁依赖内核）。crate 升格/入列走分册0 §五纪律（新 crate 同批台账+地图）。

**工具投影模型**：宿主经 `tools_list` 拿到清单后，在宿主侧 ToolsRegistry 注册**代理工具条目**（模型面只见 name/description/parameters 三元组——tools.v1 白名单纪律原样生效，timeout_ms 等零泄漏进模型面）；execute=转发 `tool_invoke` 等 `tool_result`。模型对插件工具与内置工具零感知差异（蓝图契约②「工具→模型桥」语义保持）。

## 四、安全边界

### 4.1 装载面沙箱（衔接 SandboxEnforcer，机制现成）

现成链路：`LandlockEnforcer::prepare(WorkspacePolicy) → PreparedSandbox{policy_json, command_cwd}`（sandbox lib.rs:64-97，parent 侧预编译）→ helper 进程 arg0 自唤起应用 Landlock 写白名单+seccomp 网络禁断+NNP（helper.rs，C 案）。L2 衔接=插件进程 spawn 时套同一 `prepare`：WorkspacePolicy 可写根=插件目录（`$SELF`）+permissions.writable 声明项+按 `[sandbox]` 段既定语义并入 /tmp；network_access=permissions.network 派生（MVP 恒 false）。
**未证实点（如实标注）**：helper 现服务 bash 工具（arg0 哨兵分派后 exec 目标为 bash），「exec 目标参数化为任意 argv」是勘察项（L2 开工第一步核 helper.rs:16-94 实态）。两条候选路径：①helper 增加参数化 exec；②`yunyou sandbox-exec --policy <json> -- <argv>` 子命令形态（arg0 哨兵机制同源复用）。倾向②（不绑 bash 工具内部结构，哨兵代码已实测），留 lead 裁。
沙箱总开关语义沿用：`[sandbox] enabled=false` 时插件进程**不降级直跑**——拒装报「沙箱禁用态不允许装载进程外插件」（与 bash 工具「降级直跑+meta 标注」不同：插件是外来代码，无沙箱不装载，fail-loud 优先）。

### 4.2 凭证隔离（红线：插件不得见 `~/.yunyou` 凭证）

实勘：`~/.yunyou/credentials.toml` 权限 0600（2026-11-17 实测）。隔离设计：
- **L2-MVP：凭据面整体不开闸**。env 注入白名单=空（子进程 env 只含 PATH 类宿主最低集，逐键白名单非全量继承）；协议无 credentials 词汇；manifest 声明 `permissions.credentials` 非空 → 拒装报「凭据面未开放」。MVP 插件=纯本地计算工具（hello 自举够用），攻击面最小化。
- **L2.1（占位设计，待裁）**：`credentials_get{ref}` 受控取值——宿主核对 manifest 声明名单（未声明=拒绝，fail-loud）→ resolve → 经 RPC 返回当次值；每次取值审计留痕（时间+插件 id+凭据名，不记值）；`[plugins.<id>]` 可收紧覆盖。诚实权衡：值终究要进插件进程（子进程要自持 HTTP），env 注入（方案甲）与受控 RPC（方案乙）都能送达，乙的审计/撤销/声明核对粒度强于甲且工作量近似，故占位推荐乙；根治方案丙=宿主网络代理（值不过插件进程）属 L2.2 级新基建，不混入。
- 系统红线不因 L2 改：`role('secret')` 消费器语义（蓝图契约⑤）在宿主侧不破——插件拿到的仍是「声明过的名字的值」，宿主存储/迁移/引用更新全部不经插件。

### 4.3 卸载无残尸（三层清单）

| 层 | 机制 | 依据 |
| --- | --- | --- |
| 进程层 | 卸载/禁用=shutdown 通知+killpg 进程组强杀+Drop 兜底 waitpid（PR_SET_PDEATHSIG 预设=主板死则 OS 先杀一层） | 崩溃隔离设计 §7 坑1 形状；killpg+GroupReaper 已有落码先例（task-14，7884392） |
| 注册面层 | 代理工具条目走 disposer 注销（契约①注册即 effect，逆序撤销）；/plugins 状态行随装配产物消失 | tools.v1 §5+内核热插拔标准「拨下无残尸」 |
| 文件面层 | 目录删除即卸载（L1 既有语义）；插件临时文件约定落插件目录内（写白名单同根，随目录删除一并消失） | 装载器最小方案 §3；崩溃隔离 §7 坑4 ResourceLedger 的 MVP 子集 |

### 4.4 fail-loud 全链（不静默降级）

发现层坏 manifest=聚合逐条报拒装（L1 既有）；market 新增违例各有专项人话：格式版本未知/runtime 缺失/entry 越界/插槽白名单外/凭据面未开/网络面未开——全部逐条中文报，拒该插件**不拖累其他插件**（对齐 L1「未命中不拒装」的边界观：market 装载失败=该插件 Failed 入表，不整树卸载——差异点：L1 静态校验违例是配置漂移=拒装全树 fail-loud 既有语义不变；market 运行期失败是插件自身问题=单插件 Failed）。握手失败/版本不符/超时/进程死亡=Failed 态+诊断人话入 /plugins，可经 restart() 复活（复用崩溃隔离 v1「Failed 唯一复位手段」）。**禁**：任何「沙箱不可用就裸跑」「协议不通就跳过」式降级路径。

## 五、生命周期（五态+崩溃隔离）

### 5.1 五态机（宿主侧代理 fiber 承载）

**核心架构决策：market 插件在宿主侧映射为一个轻量代理插件（ProxyPlugin，cli 域构造，经 `ctx.plugin()` 公开 API 装配）**——manifest=文件投影、setup=spawn+握手+tools_list+代理注册工具、进程即其执行体。收益：enable 开关/FiberHandle 状态（Active/Failed/Pending）/restart()/观测状态行/卸载 disposer 全部复用既有机制，**内核 crate 零改动**（装配五步/三层 enable/FiberHandle 语义原样）；新机制只剩「子进程管理」一处。

| 态 | 触发 | 表现 |
| --- | --- | --- |
| installed | plugins/<id>/ 目录+manifest 校验过（未启用或启用前） | /plugins 行 source=discovered |
| enabled | 装配装载成功：进程起+握手过+tools_list 过+代理工具注册毕 | 代理 fiber Active；工具模型面可见 |
| disabled | `[plugins.<id>] enable=false` 或 auto_enable=false | 不 spawn 无进程；/plugins 行 disabled；无残尸 |
| failed | spawn/握手/清单/调用超时/进程死亡 | /plugins 行 failed+人话原因；restart() 重拉进程复活（懒恢复） |
| uninstalled | 目录删除 | 全部状态消失；重启后零痕迹 |

**升级（upgraded）**：同目录替换文件+version 变更 → **重启生效**（/new 同效）——MVP 不做热升级，诚实标注：业主定案要求的是「安装即自动注册」，未要求热插拔；重启生效与 L1 既有「改配置重启生效（/new 立即生效）」语义同轨，不造第二套。与官方 application 五态对表：applied=enabled（装配验证毕才算生效——分册3 §五.5 验证律同构）；restart-required=升级/配置变更后的重启语义；overridden=同 id 重复声明拒装（discover 既有防呆）；failed=failed；cancelled=暂无交互安装器，N/A（L2.2 tgz 安装器引入时对表）。

### 5.2 进程模型与崩溃隔离（插件死≠主板死）

- **一插件一进程**：崩溃半径最小化；不做共享宿主进程省资源的形态（省的是内存，赌上的是隔离，不值）。
- **装配期立即拉起**（非懒拉起）：装配即验证「装了能不能跑」，握手失败当场 Failed——fail-loud 完整性优先于启动延迟；B5 基准数据出来后再评估是否给「懒拉起」选项。
- **MVP 进程看护**：child 死亡检测（wait）+单请求超时（request_timeout_ms）→ 软失败；**心跳+熔断（崩溃隔离 §7 坑3）留 L2.1**。四坑兑现节奏：坑1 孤儿收割=MVP 必做（进程模型基础件）；坑2 stderr=独立 drain 任务逐行前缀透传主板 stderr（防 64KB 管道满死锁，环形缓冲留 L2.1）；坑3/坑4=L2.1。
- **工具调用死亡归一**：插件进程在调用中死亡 → `tool/process-crashed` 错误码（对齐 executor `tool/panic` 归一先例），代理 fiber 转 Failed；下次 restart 重拉。取消：MVP 靠超时硬断；`cancel` 词汇+「等静止不 abandon」语义 L2.1 兑现（tools.v1 取消契约同构）。
- **与 S-ISO 的关系（如实标注）**：崩溃隔离设计 §8 的 PluginRunner 统一抽象（InProcessRunner/SubprocessRunner）在 task-11 闭环清单（S-ISO-2/3/4）中**未见 S-ISO-5 落库记录**——L2-MVP 不阻塞于此（ProxyPlugin 自管子进程，不依赖该 trait）；L2.1 收编 SubprocessRunner 时先核 S-ISO-5 实态，避免两套子进程管理。

## 八、反骨自查（三最大风险+替代路径）

**风险一：子进程成本未证实，B5 基准是悬顶之剑（终稿开放项1 自认）。** 若冷启动/往返实测远超预期（如每次调用 >50ms），「语言无关」论据的性价比坍塌。缓解：B5 简化基准前移进 MVP 验收（数字先行，不后移到 L2.1）；常驻进程摊薄冷启动（已选）；分流原则=高频核心工具留 bundled、低频外部能力走 L2（蓝图「新功能一律插件形态」的例外条款=主板要加强，双裁入账）。替代路径：WASM 缝（协议词汇同构、换传输层）——终稿既定观望，若基准不达标且常驻无法解，提前启线。

**风险二：协议词汇过早冻结锁死生态。** MVP 只开工具面；命令/提示段/凭据/事件面逐期加变体，每次都动封闭枚举+走评审线一——若 MVP 把词汇形状定窄（如 tool_result 只映 ToolOutcome 不留扩展位），后期加面可能破兼容。缓解：capabilities 握手占位（未知 capability 协商拒绝而非崩）+加法演进律成文（新变体=修订，旧端遇未知 type 拒帧并人话报「协议版本过旧」）+contracts 版本化（tools.v1→v2 保 v1 兼容期，终稿既定律）。替代路径：完全动态能力协商（插件自述 schema）——表达力强但校验面失控，MVP 不做，留 L2.1 评估。

**风险三：沙箱衔接面未证实+凭据面开闸后的张力。** helper exec 目标参数化是勘察项（§4.1 如实标注），若 helper 与 bash 工具耦合过深则衔接成本上浮；L2.1 凭据面开闸后「插件内凭据泄露面」是官方同款已知风险（插件化改造方案 §6 风险表第7条）。缓解：路径② sandbox-exec 子命令形态（不依赖 helper 内部结构）；凭据声明制+受控 RPC+逐次审计+可收紧覆盖，MVP 阶段凭据面整体不开闸。替代路径：插件进程不入 Landlock 而改独立低权用户+nsjail 类外置隔离——引入外部依赖与 root 面，违背「机制同构、零新依赖」倾向，不推荐，留档仅作兜底。

**附注（第四风险，不占三席但须在案）**：ProxyPlugin 映射的语义漂移——进程外插件复用宿主 fiber 状态机，restart() 语义=重拉进程重握手，若插件 setup 有非幂等副作用（建目录/写状态）会重复执行。缓解：协议文档明示「tools_list 前的初始化必须幂等」；MVP 验收③（kill-9 后重拉成功）即该语义的实测锚。
