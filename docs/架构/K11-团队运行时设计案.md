# K-11 团队运行时设计案（三层细化+协议+收敛序）

> 承办：云点｜性质：设计报裁（骨架 414ef19f v0 已批，本稿=实施前设计定稿）｜日期 2026-11-18
> 基座：蓝图终稿附二-3 K-11 对表+云枢 A 案（PDEATHSIG=launcher/收割=procmgr 三层）+K-19 八帧传输词汇基座。

## 一、三层职责细化

| 层 | 职责 | 明确不做 |
|---|---|---|
| **launcher** | worker 进程 spawn（argv 编排/env 白名单注入/PDEATHSIG=prctl(PR_SET_PDEATHSIG,SIGKILL)）——spawn 后即退（不留守） | 心跳/收割/任务图/消息面 |
| **procmgr** | 进程表（worker 注册:pid+capability+session_id/心跳超时感知/死亡事件发布）+收割（reap 僵尸/状态收敛 Unloading→hub 通报） | spawn（launcher 亡后新 worker 由 lead 侧经 procmgr API 重派——修复链接管） |
| **worker-core** | 成员运行时（proto 客户端：hello 握手/tools_list 上报/tool_invoke 消费/心跳应答）+任务执行面 | 身份裁决（=连接会话，message.v2 议题传递） |

**spawn 协议**：launcher argv=`[worker-core 路径, --session <id>, --proto-socket <path>]`——session id=连接会话标识（身份锚点）；proto-socket=宿主 IPC 套接字（run/ 目录，0700 语义继承）。
**env 白名单**：PATH+TMPDIR（K-19 §4.2 同款最小集，凭证零继承=红线）。

## 二、心跳与死亡感知

- worker→宿主：ping 30s 间隔（proto Ping/Pong 帧复用），连续 3 次超时=宿主侧判亡→procmgr 收割+hub 通报；
- 宿主→worker：PDEATHSIG=launcher 亡即 SIGKILL（launcher 不留守=无双监督打架）；
- 死亡事件：procmgr 发布 DeathEvent{pid,session_id,reason}→hub 降级续投（K-7 既有语义）→lead 升级报（K-16 ②a 语义衔接）。

## 三、收割收敛序（procmgr）

1. 死亡感知（心跳超时/waitpid 收割退出码）；
2. board 状态收敛：成员 claimed 任务→回 pending（附中断 Report=K-16 语义）；
3. hub 通报：成员下线（Pending→认领语义留给重启 worker）；
4. 修复链：lead 侧重派（launcher API=procmgr 提供 spawn 请求转发，launcher 进程由 procmgr 按需重拉——「launcher=最后死」的生存序：procmgr 先亡才轮到 launcher 亡）。

## 四、message.v2 对齐（传递不裁决）

- 传输词汇=K-19 八帧（proto crate 单源）——**身份=连接会话**在本设计=session_id 贯穿（spawn argv→proto hello→任务分派），语义深化（多会话/会话迁移）=message.v2 议题单独立项传递；
- 升等议题留位：hub 路由从「fiber 上下文」到「session_id 寻址」的宿主侧改造=K-11 验收核心面，实施批细化。

## 五、实施序（报裁后）

1. procmgr 骨架→进程表+收割（纯进程内可单测先行）；
2. worker-core 骨架→proto 客户端+心跳（K-19 proto 复用）；
3. launcher→spawn 协议+PDEATHSIG（沙箱 helper 参数化勘察=K-19 §4.1 勘察项联动）；
4. 集成：双模式验收（进程内 fiber 现态回归+进程外 worker 新链）。
