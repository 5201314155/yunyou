# K-16 自动续跑与步数预算自管理——设计案（云界受托，报 lead 裁；云络接刀底册）

> 任务链：lead 领任务令（task-62）→ 云界设计案（边界压测出身，恢复/续跑路径状态机）→ 云络实施（K-16，68 刀1 后接刀）。
> 底图：今日双案例（pipeline-reviewer MAX_STEPS=16 截断后卡死/61 挂死——DSH 侧教训，K-16 引以为鉴）+ agent-loop 现状（task-23 软着陆已入库）。
> 设计纪律：先设计不动码；涉及文件清单见 §7；验收基准见 §8；开放问题报裁见 §9。

## 1. 背景与动机

双案例共性：**多代理自动场景里，「停下等人」等于「永远停着」**——
- 案例 A（MAX_STEPS=16 截断）：步数护栏触达→软着陆等「继续」→自动场景无人回复→任务停在半途，成果与剩余工作无交代；
- 案例 B（61 挂死）：回合非正常中断（进程级）→无人检测→无人续跑→无人上报。

K-16 团队运行时的成员是**无人盯守的自动执行体**——步数预算与中断处置必须从「等人」改为「自管理+主动上报」。

|---|---|---|

## 3. 三件设计

### 3.1 ① 步数预算自管理——三段收尾模式

**状态轴**（回合内，按消耗比例）：正常段 → 预警段（≥warn_ratio）→ 触达段（=100%）→ 终态。

| 段 | 触发 | 行为 | 谁主导 |
|---|---|---|---|
| 正常段 | 消耗 <80% | 现行为（跑到模型停手） | 模型 |
| **预警段** | 步数或 token ≥`budget_warn_ratio`（默认 0.8，步末检查） | 注入一次性 SystemMessage：「预算余约 X%——请开始收尾：**增量落盘**已完成成果（写文件）、**输出阶段总结**、**申报剩余工作**（未完成项列清单）」；此后每步末若模型仍未收尾，重复提示（每次注入均落盘=上下文可见） | 引导模型自收尾 |
| **触达段** | =100% | 分模式：**自动模式**（team 成员，`auto_winddown=true` 默认）→ 触达步直接注入收尾指令（同上三件事）+ 软着陆标记，**下一回合自动带「继续」执行收尾回合**（一次，见 3.2 计数池），收尾回合产出=阶段总结+剩余申报→回合终态 `WindDown`；**人工模式**（REPL，默认）→ 现软着陆语义不变（等「继续」） | 自动=成员自管理；人工=用户 |

设计取舍：
- **「继续」在自动模式不是无限续杯**——触达后只自动续**一个收尾回合**（预算外宽限，`winddown_grace_steps` 默认 4 步硬顶），收尾回合内模型必须产出总结+申报；宽限步耗尽仍没收尾→强制终态（诚实截断，③ 上报）。防「继续×N」无限循环（案例 A 的 16 步截断即此类失控的前夜）。
- 预警注入**落盘**（SystemMessage）——重启后扫描可见=② 的进度摘要原料。
- token 与步数双护栏**先触先警**（任一进预警段即注入，二者独立计数）。

### 3.2 ② 自动续跑——重启检测、注入、上限、升级

**检测**（进程/成员重启后首回合前）：扫会话 JSONL 尾部——
- 末事件=软着陆 SystemMessage（含「回复继续」文案标记）→「软着陆中断」；
- 末事件=tool-call 无配对 tool-result →「工具执行中断」；
- 末事件=user-message 无 assistant →「孤儿输入」（task-36 已录该形态）。
三者任一=未完回合。

**续跑动作**（分模式）：
- **自动模式**（team 成员）：检测命中→自动发「继续」（新回合，完整历史天然接续）+ SystemMessage 注入续跑标记（含进度摘要：末 3 个工具调用名+最后 assistant 片段 80 字——**回放复用件**摘要化）；**上限 2 次**（计数见 §5 元数据）→超限=升级（3.3）。
- **人工模式**（REPL）：不自动发——恢复行旁加提示条「检测到未完回合（N 条记录，最后动作：…）——回复『继续』接续，或 /sessions 切换/『放弃』忽略」；用户全权。

**计数与幂等**：
- 续跑计数存**会话内事件**（新变体 `ResumeMark { round: u32, reason: String }`——JSONL ignorable 兼容：旧读取器见未知 type 跳过，不炸）——**不引入旁车元数据文件**（单一事实源原则；尾部扫描天然取到最近 ResumeMark 计数）。
- 幂等：同一未完回合的重复重启→ResumeMark.round 递增；round≥2 后检测命中**不再自动续**，直接升级。「回合身份」=尾部软着陆/孤儿标记的稳定性（续跑新回合产生新 assistant 后，旧标记不再是尾部→检测自然熄火，无需显式清位）。

### 3.3 ③ 截断检测自动化——中断上报不靠人盯

**事件源**：TurnOutcome 归类四态——`Done`（模型停手）/`WindDown`（3.1 收尾终）/`Paused`（人工模式软着陆，等继续）/`Interrupted(reason)`（取消/错误/流中断/宽限耗尽/续跑超限）。
**上报通道**（team 成员）：Interrupted 态→经 hub 自动投 lead 一条 `InterruptReport { member, reason, progress_summary, resume_round }`——**复用 K-7 Report 投递通道的反向事件**（零新通道）；REPL 单机无 lead→渲染层中断横幅（复用 ④ 恢复行样式）。
**上报节流**：同一回合的多次中断（续跑 2 次内）只发首报+末报（超限升级报），中间态不发（防告警风暴）。

## 4. 状态机总图（回合×生命周期）

```
回合内：Running ──≥80%──▶ Warned ──=100%──▶ 触达
  触达 ├─人工模式─▶ Paused（等「继续」）──用户继续──▶ Running（新回合）
       └─自动模式─▶ WindDown（宽限≤4 步收尾回合）──产出总结──▶ Done(WindDown)
                  └─宽限耗尽──▶ Interrupted(宽限耗尽)
生命周期：进程重启──尾部扫描──┬─无标记──▶ 正常启动
                            ├─未完+自动+round<2──▶ Resuming（注入续跑）──▶ Running
                            └─未完+round≥2 或人工──▶ 升级/提示条
Interrupted(reason) ──team──▶ hub 报 lead（首报+末报节流）
```

## 5. 配置面（加法演进，全部默认=现行为）

```toml
[agent_loop]
budget_warn_ratio = 0.8        # 预警段阈值（步数与 token 各自独立判定）
auto_winddown = false          # 触达自动收尾模式（team 成员插件默认 true 覆盖）
winddown_grace_steps = 4       # 收尾回合宽步硬顶

[team]
resume_max = 2                 # 自动续跑上限（超限升级）
resume_notify = true           # 中断上报 lead 开关
```

## 6. 与既有机制的关系（不重复造轮子声明）

- **不改 finish_paused 续跑机制**（上下文天然续跑已成立）——只在其上加预警段与自动/人工分叉；
- **不加旁车元数据文件**——ResumeMark 事件入账本（单一事实源+ignorable）；
- **不加通知通道**——复用 K-7 hub Report 通道反向事件；
- **不重复云探正常路径**——回放/恢复行复用 ④ 组件（sessions_cmd::render_replay）。

## 8. 验收基准（真机 PTY，TERM 纪律）

- ①a 预警段：max_steps=10+9 步消耗→第 9 步末见预警 SystemMessage 落盘；
- ①b 自动收尾：team 成员 max_steps=4+auto_winddown→触达后自动收尾回合产出总结+申报→终态 WindDown→hub 见报；
- ①c 宽限硬顶：收尾回合 4 步不收尾→强制终+③ 上报；
- ②a 重启续跑：成员回合中途 SIGKILL→重启→自动「继续」+ResumeMark round=1→再 SIGKILL→round=2→再 SIGKILL→**不再自动续**+lead 收升级报；
- ②b REPL 提示条：同场景 REPL 侧只见提示条不自动续；
- ③a 节流：连续中断只见首末两报。

## 9. 开放问题（报裁）

1. **Interrupted 退出码**：REPL 单机中断已走 130（task-59a 惯例）——team 成员的进程内中断无进程退出码概念，上报即终态——两域口径并行不冲突，确认即可。
2. **ResumeMark 是否进面板/回放**：建议不进（回放只取 user/assistant 既有口径）——确认。
3. **收尾回合的 LLM 消耗计费**：宽限步在预算外——token_budget 是否对宽限步豁免（建议豁免+winddown 消耗单独记 stats 供观测）。
4. **升级通知的 lead 不在线**：hub 信箱降级续投（K-7 已有）兜底——确认无需新机制。
