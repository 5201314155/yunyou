## 1. 网关形态（业主 D1 裁决：一期即分进程）

### 1.1 裁决留痕与现行形态

| 候选 | 结论 |
| --- | --- |
| a. yunyou-cli 内组件（网关挂大 agent Context，云枢原建议） | **被业主否决留痕**（03:47）：公网暴露面直达编排者进程，业主优先隔离、接受工期拉长 |
| b. 独立 `yunyou-gateway` bin（分进程，经会话 IPC 协议访问大 agent） | **业主裁决采纳，一期范围**；暴露面隔离干净（网关挂了大 agent 照跑，与面板同构），代价是 IPC 协议设计与联调（§2） |

- **所属层**：`yunyou-gateway` 独立 bin **无层属性**（与 launcher/probe/面板同列——它不跑组件内核，是纯网关服务）；大 agent 侧新增「IPC 服务端」组件（`ipc-server`）属**编排层插件集**。与内核方案 §2.7.2「内核只被大 agent 与员工 worker 复用」一致：网关进程不依赖 yunyou（deps-gate 新增黑名单条目）。
- **生命周期**：`yunyou-gateway` 独立启动（读网关配置 + 加载 IPC 凭证文件）；大 agent 侧 `ipc-server` 组件随 yunyou-cli 装配（配置启用）。网关崩溃不影响大 agent；大 agent 重启 → IPC 凭证轮换（§2.2）→ 网关重读凭证重连（指数退避，§2.6）。
- **权限边界**（与补注二 admin_commands 分清）：网关与大 agent 之间只有 §2 IPC 一条通道，其暴露面 ⊆ App scope 能力面（chat / panel:read / panel:write 入队），**严禁任务图直写通道**（§2.4）；网关自有 gateway.db（令牌/设备/审计），与 tasks.db 物理分离。

### 1.2 部署拓扑（一期定案）

```text
App（扫码/验证码配对 → 会话令牌）
   │  HTTPS/WSS（公网：TLS 直连或反代；内网：HTTP，token 仍强制）
   ▼
yunyou-gateway 进程（无层属性：HTTP/WS 服务 + 鉴权中间件 + token 存储 + 审计）

   ▼
yunyou-cli 进程（编排层：ipc-server 组件 + agentLoop/sessions/taskgraph…）
   └─ panel:write 命令 → admin_commands 表 → admin 组件消费（补注二路径）
```

## 2. 网关↔大 agent 会话 IPC 协议设计（业主 D1 裁决新增，一期范围）

### 2.1 传输选型：Unix domain socket + 应用层凭证

| 候选 | 分析 | 裁决 |
| --- | --- | --- |
| Unix domain socket（UDS） | 文件权限即访问控制（精确到 UID）；不占 TCP 端口、无端口扫描面；本地嗅探面最小 | **采纳** |
| 127.0.0.1 TCP | 需自选端口（占用/冲突面）；同宿主机其他 network namespace 的进程（如 bridge 容器）可能触达，需额外防火墙约束 | 备选，仅 Windows 等无 UDS 平台启用（一期目标平台 Linux，不实现） |

- **socket 文件**：`<yunyou-home>/run/gateway.sock`；`run/` 目录权限 0700，socket 权限 0600（agent 启动时强制创建/校验，已存在先安全删除防残留劫持）。
- 帧格式：**JSON Lines**（每行一消息，`\n` 分隔）——可调试、与 JSON Schema 纪律同源、一期吞吐要求低；不用二进制长度前缀（无收益徒增编解码器）。

### 2.2 IPC 凭证（进程外不可得）

- agent 启动生成 32B 随机 secret（getrandom/CSPRNG）写 `<yunyou-home>/run/gateway-ipc-secret`，权限 **0600**、目录 0700；**每次 agent 重启轮换**（网关重连时重读）。
- 握手认证：连接首帧 `hello` 携带 secret 的 SHA-256（不传明文）→ agent 比对 → `hello_ok` / 断连并审计。**双因子**：UDS 文件权限（到不了文件就连不上）+ secret（同 UID 误配进程也过不了认证）。
- 失败处理：连续 3 次认证失败 → agent 侧删除 socket 并告警（需人工介入，fail-loud——防暴力试 secret）。

### 2.3 消息族（全部 JSON Schema 2020-12 化，§8 生成落 docs/接口/schema/）

| 消息 | 方向 | 载荷要点 |
| --- | --- | --- |
| `hello` / `hello_ok` / `hello_err` | 网关→agent / 回 | secret 哈希、协议版本、resume 信息（可选） |
| `ping` / `pong` | 双向 | 心跳 30s 间隔，连续 3 次超时断开 |
| `session.open` | 网关→agent | device_id、device_name → 返回 session_id（惰性创建，§2.5） |
| `chat.send` | 网关→agent | session_id、消息内容（用户输入）→ ack |
| `chat.events` | agent→网关 | 会话事件流（assistant 增量/工具事件），带单调 `seq` |
| `panel.tasks.read` | 网关→agent | → 只读投影快照（agent 侧生成，不暴露原始表） |
| `panel.command.submit` | 网关→agent | → 入队确认（等价 admin_commands 入队，不直写） |

- **暴露面铁律（业主硬约束③）**：IPC 消息族封闭如上——**不存在**任务图直写、状态流转、花名册管理消息；新增 IPC 消息类型 = 本方案修订（评审线一），不允许实现时私加。
- `panel.tasks.read` 投影由 agent 侧编排层服务生成（只读），网关看不到 SQLite 原始内容；`panel.command.submit` 等价面板入队路径（补注二）。

### 2.4 暴露面与 App scope 的映射（业主硬约束③）

| App scope（§7.2） | 依赖的 IPC 消息 | 说明 |
| --- | --- | --- |
| `chat` | session.open / chat.send / chat.events | App 对话能力全部经此三消息 |
| `panel:read` | panel.tasks.read | 只读投影，与面板观察面一致 |
| `panel:write` | panel.command.submit | 只入队，消费权在编排层 admin 组件 |

网关不缓存任何「超越令牌 scope」的请求——中间件（§7.1）先验 scope，再选 IPC 消息；两道闸串联。

### 2.5 会话归属模型（App 设备 ↔ agent session）

- 映射：**一个 App 设备（gateway_tokens.device_id）↔ 一个 agent session**；映射存网关侧 `gateway_sessions` 表（device_id → session_id），agent 侧 `session.open` 惰性创建会话并回 session_id。
- 隔离：多设备各自独立 session（会话内容互不可见，复用内核方案会话隔离语义）；同设备重连映射到同一 session（续聊）。
- 生命周期：设备令牌吊销 ≠ 删会话——会话保留在 agent 侧（面板可观察、审计可回放），设备重新配对后续聊原会话；设备删除（DELETE /devices）时网关仅解除映射。

### 2.6 断连重连与事件补发（业主硬约束⑤）

- **事件序号**：`chat.events` 每会话携带单调递增 `seq`（源自会话事件存储的序号——会话事件本就持久化于 sessions JSONL，天然可回放）。
- **重连**：网关重连 `hello` 带 `resume: { session_id, last_seq }` → agent 从会话存储回放 `seq > last_seq` 的事件（按序）→ 补齐后恢复实时流。
- **背压语义（丢连接优于丢事件）**：agent 侧每网关连接一个**有界通道**（默认 256）；通道满（网关消费过慢）→ **断开该网关连接**——事件不丢（持久化在会话存储），网关重连走回放补发。agent-loop 主路径（写会话存储）永不被网关消费速度阻塞。
- 退避重连：网关侧指数退避（1s 起，上限 30s）+ 抖动；凭证失效（hello_err）→ 立即重读凭证文件一次，仍失效则进入长退避并告警（大 agent 可能已重启换密）。

## 3. token 体系（两段式）

### 3.1 令牌模型

| | 配对令牌（pairing token） | 会话令牌（session token） |
| --- | --- | --- |
| 形态 | `dsh_pair_<base64url(32B 随机)>` | `dsh_sess_<base64url(32B 随机)>` |
| 时效 | 一次性，默认 5 分钟 | 长期，默认 30 天**滑动过期**（业主 D5 定案） |
| 消费 | 恰好一次：换会话令牌后原子失效 | 可撤销；吊销立即生效 |
| 存储 | **哈希存储**（SHA-256(token)，库泄露不泄可用令牌） | 同左；另存设备指纹/名称/scope/创建时间/最后活跃 |
| 数量 | 每次配对会话 1 枚 | 每设备 1 枚（重配对=旧令牌吊销换新） |

- 随机源：`getrandom`（OS CSPRNG）；base64url 无填充。
- **原子一次性语义（防重放）**：`UPDATE pairings SET consumed=1, consumed_at=? WHERE token_hash=? AND consumed=0 AND expires_at>?`——影响行数 0 即已消费/过期，拒绝；并发重复消费只有一方成功。
- **吊销立即生效**：中间件查表带 **generation 缓存**（令牌表版本号内存缓存，TTL 1s）——吊销/锁定 bump generation，下一请求即失效；WS 长连接经连接注册表按令牌索引，吊销事件主动断开。
- **设备数上限（评审非阻塞建议采纳）**：活跃设备数（未吊销令牌数）上限可配，**默认 10**——配对时超限拒绝（HTTP 409 + 明确提示），防 devices 表无限增长。
- 设备管理：`GET /devices`、`DELETE /devices/{id}`（吊销单设备）、`DELETE /devices`（吊销全部）；scope 变更 = 换发新令牌（旧令牌吊销），审计留痕。

### 3.2 失败锁定与限速（业主 D7 定案：按下表执行，全部可配）

| 端点 | 限速（令牌桶） | 失败锁定 |
| --- | --- | --- |
| 配对消费（扫码/验证码共用交换端点） | 10 次/分/源 IP | 同一配对会话连续失败 **5 次 → 锁定 15 分钟**（配对会话级，落库） |
| 设备码生成 | 5 次/分/源 IP | — |
| 业务端点 | 60 次/分/令牌 | — |
| WS 握手 | 10 次/分/源 IP | — |

锁定双维：源 IP + 配对会话；公网模式源 IP 取可信反代链（§5.2）。锁定/吊销/签发/失败全部写审计（§3.3）。

### 3.3 审计日志

结构化记录落 `<yunyou-home>/logs/gateway-audit.jsonl`：事件（pair_issued/pair_consumed/pair_rejected/lock_engaged/token_issued/token_revoked/auth_failure/scope_changed/device_limit_rejected）、时间、源 IP、设备 id、结果原因码。**认证失败必留痕**；审计不可被业务端点关闭。

## 4. 配对维度：扫码与验证码

### 4.1 扫码连接

- QR 载荷（schema 落 `docs/接口/schema/配对二维码.schema.json`）：
  `{ "v": 1, "kind": "yunyou-gateway", "endpoint": "wss://gw.example.com 或 ws://192.168.x.x:7900", "pairing_token": "dsh_pair_…", "expires_at": 1699… }`
- 流程：网关生成配对令牌 + 渲染 QR（`qrcode` crate）→ App 扫码 → `POST /pair/consume`（Bearer: pairing token）→ 时效/一次性校验 → 签发会话令牌 → 设备登记（含 §3.1 设备数上限检查）。
- 防重放：§3.1 原子消费；时效 5 分钟；QR 不含长期凭证。

### 4.2 验证码连接（设备码流程，对标 OAuth Device Flow 简化版）

- 网关生成 8 位短码（字符集去掉 0O1lI 的 32 字符集，≈1.1 万亿空间）+ device_name 提示 → 界面显示。
- App：`POST /pair/device-code`（{code, device_name}）→ 校验（时效 10 分钟/尝试 ≤5 次/未锁定）→ 签发会话令牌。
- 防爆破：§3.2 限速+锁定；短码时效作废；尝试计数落库。

### 4.3 两维正交

配对方式与网络维度独立选择、任意组合；差异仅 endpoint 形态（§5），token 鉴权路径四格完全一致（§6）。

## 5. 网络维度：内网与公网

### 5.1 内网启动

- 默认绑定局域网接口（端口默认 7900，可配）。
- **发现机制（可选）**：mDNS（`mdns-sd`）广播实例名 + 端点，**默认关闭（业主 D3 定案）**；发现响应只含端点与实例名，**不含任何凭证**——发现解决「找到」，信任建立仍走配对，token 强制不豁免。
- 内网 HTTP（无 TLS，业主 D6 定案不强制）安全边界：局域网明文可见 token 传输——缓解：令牌短时效/可撤销/滑动过期；内网也全程 token，无匿名格（§6）。内网 TLS 需求（自签+固定指纹）已预留 QR 指纹字段位，按需启用。

### 5.2 公网启动

- **TLS 强制，两种部署形态（业主 D6 定案：反代为主 + 自管证书直连可选）**：
  - 反代（主推）：nginx/caddy 终止 TLS → 网关监听本地回环；网关**仅当配置可信代理 CIDR 列表时才信任** `X-Forwarded-For/Proto`（防伪造头绕过限速/审计）；
  - 直连（可选）：网关自带 TLS（rustls），配置证书/私钥路径（一期不做自动 ACME）。
- 暴露面最小化：仅网关端口开放；公网模式**禁用 mDNS**；错误响应统一形态、不泄露内部细节；配对端点限速可配收紧。
- 公网模式未配 TLS → **fail-loud 拒绝启动**并打印显式原因（对齐 dsh「misconfiguration fails loud」纪律）。

## 7. 统一鉴权中间件与 scope 边界

### 7.1 中间件设计（HTTP 与 WS 同一条链）

```text
请求 → 提取 Bearer → SHA-256 → generation 缓存查表（存在?未吊销?未过期?未锁定?）
     → scope 检查（端点要求 ⊆ 令牌 scope）→ 注入 Identity{device_id, scope} → 处理器
失败 → 401/403（无效=401 无信息；权限不足=403）→ 审计 auth_failure
```

- WS：握手走同一中间件；连接建立后消息不再逐条验 token（连接绑定设备），**吊销即断连**（§3.1 连接注册表）。
- 实现载体：axum + tower middleware（框架选型已随上轮评审确认）；网关进程为纯 tokio 服务（无组件内核）。
- IPC 侧（§2.4）：中间件验完 scope 才选 IPC 消息，两道闸串联。

### 7.2 App 会话 scope 边界

| scope | 能做什么 | 不能做什么 | 与编排层权限的映射 |
| --- | --- | --- | --- |
| `chat`（默认授予） | 建 WS 会话与 agent 对话、读自己会话事件流 | 触发任务图写、读他人会话、动花名册 | 经 IPC session.open/chat.*（§2.3 消息族封闭） |
| `panel:read`（默认授予） | 只读任务图视图/worker 列表/成本/审核队列 | 任何写 | 经 IPC panel.tasks.read 只读投影 |
| `panel:write`（默认**不**授予，业主 D4 定案） | 提交 admin_commands | 直接执行（编排层 admin 组件异步消费，补注二路径） | 经 IPC panel.command.submit 只入队 |
| `pair`（内部） | 仅配对消费端点 | 不可自取、不可升级 | 配对令牌专属 |

新设备默认 scope = `chat + panel:read`；`panel:write` 须管理员显式授予（换发令牌）；scope 变更审计留痕。边界铁律：App 能做的事 ⊆（chat 链路 + 面板权限面），网关与 IPC 均无越层通道。

## 11. 风险点（云枢自标，按 D1 裁决重排）

1. **IPC 凭证泄露面（中）**：secret 文件 0600 + run 目录 0700 + 首帧哈希认证 + 重启轮换已把「进程外不可得」做实；残余风险 = **同 UID 本地进程**可读凭证文件（本地提权后的攻击不在防线内——威胁模型明示：同 UID 进程属可信域）。部署文档必须写明该边界。
2. **UDS 在容器/多用户环境的注意点（中）**：UDS 权限随宿主 UID 语义——跨 UID 容器共享 volume 挂载 run/ 目录会暴露 socket；回环 TCP 备选在 bridge 网络下有同宿主机触达风险。约束：网关与大 agent **同 UID 部署**（同容器或同用户 systemd 单元）；部署文档给容器化清单（volume 不含 run/ 或共享 PID/UID 命名空间）。
3. **IPC 背压「断连+回放」的正确性（中）**：丢连接优于丢事件的设计依赖回放语义严格（seq 单调、last_seq 前事件不重发、跨重启回放一致——回放源是持久会话存储）。对策：ipc_protocol 测试覆盖「补发顺序/去重/跨 agent 重启回放」三例；回放实现复用 sessions 存储读取路径，不自造第二份事件读取逻辑（模块化纪律）。
4. **WS 长连接的吊销时延（中）**：generation 缓存 TTL 1s 内存在吊销生效窗口；WS 靠主动断连即时生效，断连前在途消息不可撤回。缓解：吊销即断 + 在途消息审计。
5. **内网明文 HTTP（低-中）**：局域网嗅探可见 token（D6 定案不强制内网 TLS）；缓解：令牌短时效/可撤销/滑动过期；QR 指纹字段位已预留，按需启用自签 TLS。
6. **双 SQLite 运维面（低）**：gateway.db 与 tasks.db 各自 schema_meta 单调迁移、无跨库事务（令牌与任务状态本无一致性要求）；文档写明各自备份策略。
