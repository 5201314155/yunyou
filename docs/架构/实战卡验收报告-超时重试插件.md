## 3. 真实演练（两路，真实输出全文）

演练场：调试场/演练-任务18/（Python3 标准库 mock 端点，双实例 18317/18318，每笔请求记数落日志；验证后整场已清）。二进制=target/debug/yunyou（构建 BUILD_EXIT=0，未触 release 防隐式发布）。

### 3.1 场景 A：超时失败路（mock 恒慢 10s，预算 2s）

```text
$ ./target/debug/yunyou --config 场景A超时.toml --home homeA --task "只回复四个字：演练成功"
[对话失败] Internal: llm/timeout: 请求 http://127.0.0.1:18317/v1/chat/completions 超时预算耗尽: error sending request for url (…)
场景A_EXIT=0        real 0m2.053s
mockA_requests.log：#1 12:47:32.773 POST /v1/chat/completions   ← 计数=1
```

判读：2.05s 触发预算（=2s 预算）；失败归类 `llm/timeout`（第 1 轮评审 P1「超时误归可重试类」的修复在**运行态**实证成立）；**mock 恰收到 1 次请求=零重试铁证**（若重试循环存在，应见 2s+退避+2s…共 3 次尝试、总时长 ≈7.5s+）。

### 3.2 场景 B：成功路（mock 快 0.2s，预算 30s）

```text
$ ./target/debug/yunyou --config 场景B正常.toml --home homeB --task "只回复四个字：演练成功"
演练成功-快0.2s        ← mock 回文完整回显
  ── YunYou 本回合 205ms · ↑— ↓— · mock-fast ──
场景B_EXIT=0        real 0m0.259s
mockB_requests.log：#2 12:48:59.221 POST /v1/chat/completions   ← 计数=1
```

判读：非超时路径链路本身正常（装配/请求/流解析/渲染闭环），场景 A 的失败确系超时路径专属行为，两路构成对照。

### 3.3 任务书原定「重试→最终成功/最终失败」两路的说明

因 S10 缺席，重试无从发生，该两路**不可演练**——本报告以 §3.1/§3.2 实测（超时一次即败+零重发+成功路对照）＋ §2 代码证据（零消费点）共同证明「无重试行为」，属缺陷实证而非验收通过项。补救演练条件：S10 落地后同法重演（mock 支持按次数切换慢/快，可一次跑出「首试超时→重试→成功」与「恒慢→重试 2 次→预算耗尽失败」两路）。

### 3.4 演练副产物观察（如实记，不影响本卡结论）

- 装配层存量明文 key 迁移（匠二 S5 migrate）在演练中真实触发：两份演练 toml 的 `api_key` 明文被改写为 `$YUNYOU_LLM_API_KEY` 凭据引用并提示迁移——S5 迁移链路顺带获得一次真实运行态实证。
- 超时失败 `EXIT=0`：错误优雅呈现不崩进程（与任务17 坏 key 401 优雅先例同口径），符合 M2 以来行为约定。
