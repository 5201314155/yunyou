## 一、预设 schema（settings.json `modes` 段）

**参照**：DSH PermissionCatalog/PermissionCatalogDirectory（ui-permission-presets/src/client/catalog.ts:15、settings-store.ts:48 `defaultPreset ?? catalog.defaultPreset`——预设=目录条目+新会话默认值两层）；claude 五外模式+每模式元数据表（PermissionMode.ts:43+ PERMISSION_MODE_CONFIG：title/shortTitle/symbol/color/external 五字段）。

```jsonc
// ~/.yunyou/settings.json（分源：user < project < local，复用总表 #5 分源）
"modes": {
  "defaultPreset": "标准",            // 新会话默认（DSH settings-store.ts:48 同义）
  "presets": [                        // 预设=模式的打包视图，非新模式
    {
      "name": "标准",
      "mode": "default",              // 底层模式（见状态机枚举）
      "title": "标准",                // 显示名（claude PermissionMode.ts title 字段同义）
      "symbol": "",                   // 状态栏符号（claude symbol 字段）
      "allow": [], "ask": [], "deny": [],   // 预设自带权限规则覆盖（追加语义，不替换全局段）
      "autoAllowSandboxed": true,     // 沙箱自动放行开关（总表 #6）
      "tools": "*"                    // 工具池裁剪："*" | 工具名数组（claude coordinatorMode.ts:29 INTERNAL_WORKER_TOOLS 思路）
    },
    { "name": "规划", "mode": "plan", "symbol": "⏸", "tools": ["read","glob","grep","ask_user_question","exit_plan"] },
    { "name": "放手", "mode": "acceptEdits", "autoAllowSandboxed": true }
  ]
}
```

设计要点：①**模式（mode）是内核枚举，预设（preset）是配置打包**——预设不进状态机，只在会话启动/切换时展开为 mode+规则覆盖+工具池；②预设规则「追加不替换」，全局 permissions 段仍生效（deny 永远压过预设 allow，与审批链 deny>ask>allow 序一致）；③工具池裁剪挂 getTools 过滤（总表 #1 tools.ts:262-271 已证）。

## 二、模式切换状态机

**枚举（第一期只做 4 态）**：`default → acceptEdits → plan → bypassPermissions`（dontAsk/auto/bubble 为演进位，claude types/permissions.ts:16-27）。

```
状态转移表（U 模型发起须审批，D 显示层直接切，K 键位 chat:cycleMode 循环）：
default ──U(enter_plan)──→ plan        plan ──U(exit_plan)+审批──→ default 或 acceptEdits
default ⇄ acceptEdits（D/K 直切）      任意态 ──U(bypass)+显式确认──→ bypass（一次性会话态）
bypass ──任意拒绝/危险事件──→ default（claude bypassPermissionsKillswitch 同义）
plan 态内：只读工具放行，写类工具一律 Deny（permissions.ts:1270-1280 plan 分支实证）
```

- 切换载体=**工具对**（EnterPlanMode/ExitPlanMode 成对，Exit 交计划待批=审批物是文件、工具只发信号——总表 #11 已证 ExitPlanModeTool.ts:203「审批前拒绝以免弹框」）：模型发起切换必须走工具+审批，显示层（状态栏/键位）切换不经审批。
- 状态存 ToolPermissionContext（会话态，session-meta 事件随会话恢复——总表 #4）；不落 settings（「会话级不落盘」，claude effort max 同纪律）。
- getNextPermissionMode 纯函数（claude utils/permissions/getNextPermissionMode.ts）单源计算下一态，键位循环与 UI 提示共用。

## 三、与权限审批插件交互矩阵（→ 与 yun-suo 稿的裁决交集）

| 模式 | 审批链行为（链序见《挖矿-权限审批》§二） | plan 交互点 | 归属 |
|---|---|---|---|
| default | 全链：deny→ask→工具自判→安全检查→沙箱缝→allow→Ask（含 suggestions 三态 UI） | — | yun-suo |
| acceptEdits | fs 写类工具在「工具自判」层直接 Allow（claude :604-647 用同一 checkPermissions 换 mode 试算实证——**复用同链，不另写快路径**） | — | yun-suo（试算逻辑）/本稿（模式语义） |

**两句裁决请求**：①plan 的「写类工具 Deny」发生在状态机层（工具池准入）还是审批链层（checkPermissions）？我建议**状态机层**（plan 预设直接裁工具池+只读白名单），审批链只处理 ExitPlan 一个请求——改动面最小。②acceptEdits 的放行复用同一条审批链做「换 mode 试算」（claude 实证做法），yun-suo 不必为 acceptEdits 单写旁路。
