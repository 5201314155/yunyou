# manifest.v1 契约示例

> 配套 `规格.md`。示例取自真实组件形态（tools 插件）与 validate_manifest 实测违例文案（manifest.rs:122-164）。

## 示例 1：完整组件 manifest（Rust，好例）

```rust
use yunyou::{manifest_ui::UiEntry, projection_of, PluginLevel, PluginManifest, ServiceId};

impl Plugin for ToolsPlugin {
    fn manifest(&self) -> PluginManifest {
        PluginManifest {
            id: "yunyou-tools".into(),                    // bundled 用 crate 名
            version: env!("CARGO_PKG_VERSION").into(),    // 0.1.0
            level: PluginLevel::Bundled,
            contracts: vec!["tools.v1".into()],           // 自供 tools.v1
            provides: vec![projection_of::<dyn RegistryService>()],  // "dyn RegistryService"
            inject: vec![],                               // 与 trait inject() 同源（此组件无依赖）
            ui: vec![UiEntry::Settings { section: "tools".into() }],
            auto_enable: true,
        }
    }
}
```

## 示例 2：最小合法 manifest（默认推导形态）

```text
Plugin::manifest() 默认实现（未覆盖时）：
  id = name()                                  // 如 "dummy"
  version = CARGO_PKG_VERSION                  // 如 "0.1.0"
  level = Bundled, auto_enable = true
  contracts = [], provides = [], inject = [], ui = []
```

注意：默认推导的 `contracts` 为空——`validate_manifest` 会报「contracts 不得为空」；组件**必须覆盖** manifest() 补齐契约声明（最小合法形态至少一项，如 `["svc.v1"]`）。

## 示例 3：manifest JSON 序列化形态（诊断/面板展示用）

```json
{
  "id": "yunyou-tools",
  "version": "0.1.0",
  "level": "bundled",
  "contracts": ["tools.v1"],
  "provides": ["dyn RegistryService"],
  "inject": [],
  "ui": [{ "kind": "settings", "section": "tools" }],
  "auto_enable": true
}
```

UI 条目 tag 形态（S8 冻结）：`{"kind": "command", "name": "plugins"}`；`{"kind": "page"}` 解析接受但一期拒装；`{"kind": "ghost"}` 解析即拒（封闭集）。

## 示例 4：装载前校验违例输出（四条规则各一）

```text
# ① inject 双向一致违例
trait inject() 声明了 dyn Llm 但 manifest.inject 缺失（双向一致违例）
manifest.inject 声明了 dyn Ghost 但 trait inject() 未声明（双向一致违例）
inject 服务键 ServiceId(Typed(…)) 无投影登记：manifest 侧必须经 projection_of 声明

# ② contracts 规则违例
contracts 不得为空：需声明对齐的插槽规格版本（如 tools.v1，方案 §2.5）
contracts 项 "svc" 格式非法：应为 name.vN（v+纯数字）

# ③ 服务键拼写违例
服务键 "TestSvc" 不符投影规则：应为 "dyn <TraitName>"（projection_of 投影形态）

# ④ ui 条目违例
ui 条目 settings.section 不得为空（应指向自身 config_schema 的段名）
ui 条目 kind=page 属二期 App 面预留（方案 §4.2）：一期宿主无承载面，拒装
```

违例处置：清单非空→**拒装**并逐条报出（S2 装配序列装载前调用）；不静默降级。

## 示例 5：服务键投影（projection_of 用法）

```rust
// 组件 manifest 的 inject/provides 一律经 projection_of 生成（与 ServiceId::of 同类型参数）：
let key = projection_of::<dyn Llm>();        // → "dyn Llm"（深路径取尾段规范化）
let sid = ServiceId::of::<dyn Llm>();        // 内核类型键；两者同源
// trait 侧 inject() 返回 vec![ServiceId::of::<dyn Llm>()]
// manifest 侧 inject 写 vec![projection_of::<dyn Llm>()]
// ——两侧不同步（任一方向）都会被 validate_manifest 第①条抓出（DriftSvc 漂移反例测试实证）
```
