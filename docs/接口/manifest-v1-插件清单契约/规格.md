> **契约 ID**：`manifest.v1`（本契约约束插件声明面自身；插件在 `contracts` 字段声明的各插槽契约 ID 清单见 §7）｜**状态**：**已实现**（S1 落地入库，六包 56 测试绿，2026-11-13 台账交付记录；UI 条目 schema 随 S8 冻结）
> **权威源**：`crates/yunyou/src/manifest.rs`（304 行，2026-11-14 实测）＋`crates/yunyou/src/manifest_ui.rs`；裁决 D1（代码内真源）见《插件化改造方案》§8
> **底素材**：`.dsh/skills/yunyou-plugin-dev.md`（项目级技能，本文与其速查表同源不冲突）
> **适用读者**：插件作者（bundled 组件/二期 market 包）。示例见同目录 `示例.md`。

## 1. PluginManifest 九字段

| # | 字段 | 类型 | 约束与语义 |
| --- | --- | --- | --- |
| 1 | `id` | String | 全局唯一；bundled 用 crate 名（如 `"yunyou-tools"`），market 用包名 |
| 2 | `version` | String | 插件自身版本（semver；组件覆盖时取自身 crate 的 `CARGO_PKG_VERSION`） |
| 3 | `level` | PluginLevel | `bundled`（编译期注册，禁用仅影响启用态，不可卸载）/ `market`（二期子进程协议分发，可卸载） |
| 4 | `contracts` | Vec\<String\> | 对齐的插槽规格版本，格式 `name.vN`；**非空**且格式合法（§6）；含自供与消费合集（消费视图可由 inject∩contracts 派生，S1 审查裁定） |
| 5 | `provides` | Vec\<String\> | provide 的服务键字符串投影（`projection_of` 生成）；面板/诊断展示用 |
| 6 | `inject` | Vec\<String\> | 与 `Plugin::inject()` **严格同源**的冗余声明（同一类型参数清单经 `projection_of` 投影），供装载前静态校验一致性 |
| 7 | `ui` | Vec\<UiEntry\> | UI 注册缝贡献（§3）；一期可为空数组 |
| 8 | `auto_enable` | bool | 默认启用；`yunyou.toml [plugins]` 段可覆盖 |
| 9 | `config_schema` | — | **不进 manifest 结构**：由既有 `Plugin::config_schema()`（schemars 派生）承载，避免 schema 字符串化损耗（S1 审查注记） |

落盘形态（裁决 D1）：**代码内 `Plugin::manifest()` 为真源**；schemars 生成落盘的文件形态留 market 级二期。`Plugin::manifest()` 默认实现由 `name()`+`CARGO_PKG_VERSION` 推导最小 manifest（level=bundled/auto_enable=true/其余空）——组件应覆盖补全（测试锁：默认推导用例）。

## 2. 装载时序

宿主启动：读全部 manifest → **装载前静态校验**（§5）→ 违例即拒装并逐条报出（中文违例清单，不静默降级）→ 通过才进入装配（表驱动，`yunyou.toml [plugins]` 启用表）。契约版本兼容比对（插件要的版本宿主不提供→拒装报「插槽版本不符」）随 S2 装配接入；对齐官方 plugin-manager evaluatePluginCompatibility 先例（插件化改造方案 §2.5 已引）。

## 3. UI 注册缝条目（UiEntry，S8 冻结 schema）

serde 标签枚举（`#[serde(tag = "kind", rename_all = "lowercase")]`）：

| kind | 字段 | 一期宿主承载 | 校验 |
| --- | --- | --- | --- |
| `settings` | `section: String` | settings 投影服务渲染表单描述（指向自身 config_schema 的段，零界面代码） | section 非空 |
| `command` | `name: String` | REPL 命令表（一期 schema 冻结、宿主命令表二期接；声明面先冻结防破格式） | name 非空、不含斜杠 |
| `page` | （空变体） | **二期 App 面预留**：一期宿主无承载面，**拒装** | 未知字段忽略=向前兼容；未知 kind 拒绝（枚举封闭集） |

> 注：lead 令中的「skills 注册缝」按 manifest **UI 注册缝**落（本节）；`.dsh/skills/` 技能注册是 DSH 宿主级机制（项目技能位 rank 100），非 yunyou 契约面，不在本契约——若 lead 本意另有所指，请指出补节。

## 4. 服务键投影规则

服务键在内核是 `ServiceId`（`TypeId` 类型键，运行期不携带名字），manifest 侧是字符串；投影在「类型在手上」的调用点完成：

- **唯一合法入口** `projection_of::<P>()`：把 `type_name::<P>()` 规范化为 `"dyn <TraitName>"`（取尾段，如 `"dyn yunyou_llm::Llm"` → `"dyn Llm"`）并登记进程级投影表（幂等、只增不改）。
- 组件 manifest 的 `inject`/`provides` 字符串**一律经 `projection_of` 生成**（与 `ServiceId::of::<P>()` 同一类型参数）；校验器对 trait `inject()` 的键查表反查后集合比对——trait 侧加键而 manifest 未同步（或反向）均被抓（漂移反例 DriftSvc 测试实证）。
- 拼写格式：`"dyn <TraitName>"`——尾段标识符（字母/数字/下划线，首字符字母或下划线），不含路径。

## 5. 装载前校验 validate_manifest（四条规则）

`validate_manifest(plugin, manifest) -> Vec<String>`（空=通过；违例=中文清单逐条报，**拒装**）：

| # | 规则 | 违例示例 |
| --- | --- | --- |
| ① | inject 双向一致：trait `inject()` 键查投影表后与 manifest.inject 集合相等 | 「trait inject() 声明了 dyn Llm 但 manifest.inject 缺失（双向一致违例）」；「manifest.inject 声明了 dyn Ghost 但 trait inject() 未声明」；键无投影登记单独报 |
| ② | contracts 非空且每项合 `name.vN` 格式 | 「contracts 不得为空」；「contracts 项 "svc" 格式非法：应为 name.vN（v+纯数字）」 |
| ③ | inject/provides 服务键拼写合投影规则 | 「服务键 "TestSvc" 不符投影规则：应为 "dyn \<TraitName\>"」 |
| ④ | ui 条目校验（§3 表） | 「ui 条目 settings.section 不得为空」；「ui 条目 kind=page 属二期 App 面预留：一期宿主无承载面，拒装」 |

## 6. contracts 命名格式（`name.vN`）

name 非空（首字符字母或下划线，可含 `.`/`-`/`_` 做层级与连字），版本 `v`+纯数字：

- ✓ `tools.v1`、`system-prompt.v1`、`a_b.v12`、`cordis.loader.v1`
- ✗ `tools`（无版本）、`tools.v`（空版本）、`tools.V1`（大写）、`.v1`（空名）、`1tool.v1`（数字开头）、`tools.v1.x`（多段版本）
