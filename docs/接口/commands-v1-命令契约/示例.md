# commands.v1 契约示例

> 配套 `规格.md`。示例取自真实实现形态（yunyou-commands 与 yunyou-cli/skills.rs），可作命令作者模板。

## 示例 1：插件注册业务命令（标准模板）

```rust
use yunyou_commands::{CommandDefinition, CommandKind, CommandOutput, CommandsService};
use std::sync::Arc;

// 插件 setup 内（已 inject dyn CommandsService）：
fn register_tools_info(commands: &dyn CommandsService, fiber: &Context) -> yunyou::Result<()> {
    let disposer = commands.register(CommandDefinition {
        name: "tools-info".into(),                       // 不带斜杠
        aliases: vec!["工具信息".into()],                 // 中文别名合法
        description: "列出当前注册的工具与来源插件".into(),
        kind: CommandKind::Action,                       // 动作类：执行即生效
        handler: Arc::new(|inv: CommandInvocation| Box::pin(async move {
            // handler 在宿主执行：参数与结果不进模型请求（硬约束①）
            Ok(CommandOutput::success(format!("当前输入行：{}", inv.raw_input)))
        })),
    })?;
    // 注册即 effect（硬约束②）：fiber 卸载自动除名，不留残尸
    fiber.effect("cmd:tools-info", move || Ok(Some(disposer)))?;
    Ok(())
}
```

## 示例 3：别名解析（精确名优先，测试实证语义）

```text
注册：{ name: "help", aliases: ["帮助"] } 与 { name: "hui", aliases: ["help-zh"] }

find("help")      → help 命令      # 精确名命中，即使别的命令别名也想叫 help——别名不遮蔽精确名
find("帮助")      → help 命令      # 未命中精确名，遍历别名命中
find("help-zh")   → hui 命令       # 别名表内解析
find("hell")      → None           # 未知 token → None（不进任何日志）
find("")          → None           # 空 token → None

handler_of 与 find 同一解析规则（单源，分发入口不会与目录展示解析不一致）
```

## 示例 4：D1 二分的两形态（Action vs Expand）

```text
# Action（动作类）：handler 有副作用，结果直接上屏
/help → 面板列出全目录（文案从注册表生成，新增命令自动进帮助）

# Expand（展开类）：handler 零副作用，产出回填文本
/deploy → handler 读技能文件正文 → REPL 把正文回填输入框（不自动发送）
        → 用户可增删改后手动发送 → 模型面内容由「用户消息」承载
        → 命令面零进模型（两约束：技能进命令 ∧ 命令不进模型——D1 二分同时满足）
```

## 示例 5：会话日志配对（command-run / command-done JSONL 形态）

```jsonc
{"type": "command-run",  "command_id": "7c9e…", "name": "help",   "raw_input": "/help"}
{"type": "command-done", "command_id": "7c9e…", "kind": "Success", "text": "/help 看命令…"}
// 配对纪律：command_id=UUID 铸造；run 先于 handler、done 后于结算；
// thrown/aborted 结算为 Error；旧读取器遇新 tag 走 ignorable 跳过不炸（版本门=tag 探测）
// 未知命令（handler_of=None）：不落任何命令事件——零落盘语义
```

## 示例 6：技能文件 → register 调用链（skills 注册缝的正确落点）

```rust
// 宿主/应用层机制（lead 裁定）：skills 扫描不是独立契约，落点=本缝 register。
// 槽位（D4 裁决双扫描）：项目根 .yunyou/skills 优先 + .dsh/skills 过渡兼容；
// 文件名（去 .md）=命令名；description=frontmatter description 或首个一级标题。
fn register_skill_commands(commands: &dyn CommandsService, fiber: &Context) {
    for file in scan_skill_dirs(&[".yunyou/skills", ".dsh/skills"]) {
        let Some(name) = valid_skill_name(&file) else {          // ^[a-z][a-z0-9_-]*$
            eprintln!("[技能] 文件名非法，跳过：{}", file.display());   // 点名但不拒装其他
            continue;
        };
        let path = file.clone();
        let def = CommandDefinition {
            name,                                                // 文件名=命令名
            aliases: frontmatter_alias(&file),                   // 可选中文别名
            description: first_heading_or_description(&file),
            kind: CommandKind::Expand,                           // 技能命令固定展开类
            handler: Arc::new(move |_inv| {
                let text = std::fs::read_to_string(&path).unwrap_or_default();
                Box::pin(async move { Ok(CommandOutput::success(text)) })  // 回填文本
            }),
        };
        match commands.register(def) {
            Ok(disposer) => { let _ = fiber.effect("skill-cmd", move || Ok(Some(disposer))); }
            Err(e) => eprintln!("[技能] 注册冲突，跳过：{e}"),          // 同名 fail-loud→警告跳过
        }
    }
}
// 会话换装配（/new）=旧装配 fiber 卸载→技能命令随 effect 除名→新装配重扫注册
```
