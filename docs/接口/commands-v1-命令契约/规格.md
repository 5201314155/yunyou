## 1. 定位与三层边界

命令体系三层（设计 §一）：**主板面**=本契约（注册表/目录查询/分发入口，落 yunyou-commands crate）；**插件面**=各命令本体（插件内 register）；**CLI 壳面**=补全面板渲染+壳自有命令（/help /quit /new）。命令注册是宿主 UI 缝基础设施——任何 UI 适配器（CLI 补全面板/未来 App 面板）都要「列目录+分发」，与 Context 服务注入、事件五分发同级；本缝不承载任何业务语义（业务在各命令 handler 里）。

## 2. 硬约束三条（模型隔离，实现批红线）

1. **命令面零进模型**：handler 在宿主执行，参数与结果**不进模型请求、不占工具白名单**（本 crate 与 agent-loop 无依赖边，结构上不可达；组 prompt 词汇表不加 command-*）。
2. **注册即 effect**：`register` 返回 `Disposer`，注册方应将其登记为本 fiber 的 effect（与 `ctx.effect` 同语义）——fiber 卸载即从目录除名，热插拔不留残尸（测试：注册即effect随fiber卸载除名）。
3. **同名 fail-loud**：同名重复注册返回 `Err(ServiceDuplicate)` 并点名命令名（报错文案：`命令 "/<name>" 已注册，拒绝静默覆盖`），严禁静默覆盖（防注册面互相遮蔽）。

## 3. 服务 trait（四方法）

> 实测口径：trait 方法面为**四方法**（lib.rs:147-164）；D1 二分/别名规则/零落盘语义为类型与语义面（§4/§5），非 trait 方法。

```rust
pub trait CommandsService: Send + Sync {
    /// 注册命令；同名已存在 → Err(ServiceDuplicate) 点名命令名（fail-loud）。
    /// 返回 Disposer 执行即从目录除名（幂等；注册表实例析构后变 no-op，不悬挂）。
    fn register(&self, def: CommandDefinition) -> Result<Disposer>;

    /// 全量目录：name 字典序稳定输出（提示词/面板可复现）。
    fn list(&self) -> Vec<CommandDescriptor>;

    /// 解析入口：精确 name 优先，其次 aliases；别名不遮蔽任何精确名。
    fn find(&self, token: &str) -> Option<CommandDescriptor>;

    /// 分发入口：按 find 同款解析规则取 handler（同一解析规则单源）。
    /// 未知命令/别名 → None（调用方提示，不进任何日志——官方语义：语法/未知名
    /// 未进 handler 即不落日志）。
    fn handler_of(&self, token: &str) -> Option<CommandHandler>;
}
```

解析规则细节（registry.rs 实现语义）：key=精确名的 `BTreeMap`（字典序即 list 稳定序）；**别名不建索引**——find/handler_of 先查一次精确名，未命中再按字典序遍历各命令 aliases（命令量级 <100，O(n) 遍历换单表维护，不引入双表同步的写分歧）；「别名不遮蔽任何精确名」由「先查全表精确名、再遍历别名」的顺序直接保证（测试：别名解析与精确名优先）。

## 4. 数据形态

```rust
/// 命令二分（设计决策点 D1，关键裁决）：
pub enum CommandKind {
    Action,   // 动作类：handler 在宿主执行、结果文本上屏（/help /quit /new 类）
    Expand,   // 展开类：零副作用，产出「输入框回填文本」交用户确认后作为普通
              // 用户消息发送——技能命令归此类（否则「技能进命令」与
              // 「命令不进模型」两约束相抵）
}
/// 命令定义（注册入参）：name 不带斜杠；aliases 可含中文（/帮助 /退出 /新建）
pub struct CommandDefinition {
    pub name: String, pub aliases: Vec<String>, pub description: String,
    pub kind: CommandKind, pub handler: CommandHandler,
}
/// 目录条目（list 只读投影，面板消费；不含 handler——目录是数据面）
pub struct CommandDescriptor {
    pub name: String, pub aliases: Vec<String>, pub description: String, pub kind: CommandKind,
}
/// handler 入参：一期最小面=原始输入行（command_id 铸造与 command-run/done
/// 落盘由执行方 CLI 分发层负责——handler 不管日志）
pub struct CommandInvocation { pub raw_input: String }
/// handler 返回：结算结果+文本（动作类=上屏文本；展开类=回填文本；失败=错误说明）
pub enum CommandResultKind { Success, Error }
pub struct CommandOutput { pub kind: CommandResultKind, pub text: String }
pub type CommandHandler =
    Arc<dyn Fn(CommandInvocation) -> BoxFut<'static, Result<CommandOutput>> + Send + Sync>;
```

## 5. 会话日志配对（command-run / command-done，D2 裁决摘要）

- 零新增机制：复用会话 JSONL 既有 ignorable（tag 探测即版本门，旧读取器遇新类型自动跳过不炸——既有行为实证非新承诺）。
- 两枚事件：`CommandRun { command_id, name, raw_input }`（tag=`command-run`）/ `CommandDone { command_id, kind: Success|Error, text }`（tag=`command-done`）。
- 配对纪律：`command_id`=UUID 每次调用铸造；run 先于 handler、done 后于结算（thrown/aborted 结算为 Error）——与 tool_call/tool_result 配对同构。
- 语义边界：命令事件是**纯日志配对**（回放/审计），不进模型上下文组装；未知命令不落任何事件（§3 handler_of None 语义）。

## 6. 装载与消费

- `CommandsPlugin`（id=`yunyou-commands`，bundled，无依赖）：setup 内 provide `CommandRegistry` 实例（显式擦除 `Arc<dyn CommandsService>`——泛型推断会把 P 定为具体类型导致 `get::<dyn CommandsService>` 类型不符，session 插件同款坑，plugin.rs:44-46 注记）。
- 消费方：manifest `inject` 声明 `dyn CommandsService` → 内核 epoch 机制等本服务 Active 再装载（**清单顺序不构成正确性依赖**）。
- 锁纪律：`RwLock<BTreeMap>` 读写锁绝不跨 await（内核 §2.3 同款）；disposer 只持弱引用。
- 作用域 shadow（per-agent 变体）：一期只做全局层，层枚举占位不做（「预留位不占位」同 volatile 纪律）。

## 7. 声明面配对（manifest_ui Command 兑现）

S8 冻结的 `UiEntry::Command { name }` 兑现为：插件内 `ctx` 注册命令——**声明面与实现面配对**：manifest 声明的 command.name 与 register 的 def.name 不一致 → 装载校验 **warn**（stderr 点名，不拒装——register 可晚于 manifest 校验发生，硬拒会误伤延迟注册）。

## 8. 内置命令与技能扫描（应用层，消费本缝的既有实例）

| 命令 | 类 | 语义 |
| --- | --- | --- |
| `/help` | Action | 文案**从注册表生成**（name+aliases+description；帮助文案禁硬编码——新增命令自动进帮助） |
| `/quit` | Action | 退出信号（既有硬编码迁移示范件） |
| `/new` | Action | 新会话文件+换装配+清屏重印（旧文件保留；失败路径 fail-loud） |
| 技能命令 | Expand | **双槽扫描**（D4 裁决）：项目根 `.yunyou/skills` 优先 + `.dsh/skills` 过渡兼容；文件名（去 .md）=命令名，正文=回填文本，frontmatter 可写 `alias: 中文名` |

技能文件守卫：文件名不满足 `^[a-z][a-z0-9_-]*$` → 跳过+stderr 点名该文件（不拒装其他技能）；与已注册命令同名 → register Err 由缝 fail-loud，扫描器捕获后警告跳过。

## 9. 技能文件 → register 调用链（skills 注册缝的正确落点）

lead 裁定（2026-11-14）：**skills 文件扫描是宿主/应用层机制，其契约落点=本契约的 `register`**——不是独立契约。调用链：REPL 装配 → 扫描双槽技能文件 → 逐文件构造 `CommandDefinition{name=文件名, kind=Expand, handler=读文件正文回填}` → `commands.register(def)` → Disposer 登记为装配 fiber effect（会话换装配=旧技能命令随卸载除名，/new 后重扫注册）。完整代码骨架见 `示例.md` 示例 6。
