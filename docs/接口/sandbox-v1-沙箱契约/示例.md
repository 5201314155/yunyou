# sandbox.v1 契约示例

> 配套 `规格.md`。示例为已批设计的接口形态（S11 实现批前的教学形态），以权威设计 `docs/架构/沙箱插件设计.md` 为准。

## 示例 1：策略 JSON 载荷（helper `--policy-json` 参数体）

```json
{
  "policy_version": 1,
  "writable_roots": [
    "/home/wu/agent/yunyou",
    "/dev/null",
    "/tmp",
    "/tmp/yunyou-tmp-X7f2"
  ],
  "network_access": false
}
```

说明：路径全部 canonicalize 后绝对路径；`policy_version` 不被 helper 识别即拒执行（fail-closed）；v1 的 `network_access` 恒 false。

## 示例 2：helper 命令行形态（arg0 自唤起）

```bash
# parent（BashTool）spawn 的实际命令形；-- 后为用户命令（分隔防误解析）
/home/wu/.local/bin/yunyou \
  yunyou-sandbox \
  --policy-json '{"policy_version":1,"writable_roots":["/home/wu/agent/yunyou","/dev/null","/tmp"],"network_access":false}' \
  -- \
  cargo test -p yunyou-tools
```

- helper 应用 Landlock+seccomp 后 `execvp` 用户命令换映像：PID 不变，parent `wait` 到的就是用户命令本体（退出码/信号天然透传）。
- pre-main 加固三件套：`PR_SET_DUMPABLE=0`＋`RLIMIT_CORE=0`＋清洗 `LD_*` 环境变量。

## 示例 3：插件配置（yunyou.toml）

```toml
[plugins.yunyou-sandbox]
enable = true

[plugins.yunyou-sandbox.config]
enabled = true          # false=显式降级：直跑+warn+结果 meta 标注 unsandboxed（热调）
writable_tmp = true     # false=可写根去掉 /tmp 与 TMPDIR
network_denied = true   # 网络禁断；改此项重启生效（不热调——运行中放开网络=安全面突变）
```

## 示例 4：降级与失败的用户可见形态

```text
# ① 显式降级（enabled=false）：命令照跑，结果 meta 标注（不静默）
[沙箱未生效] 本命令在无沙箱状态下执行（sandbox.enabled=false）

# ② fail-closed（内核无 Landlock/规则构建失败）：拒执行，不回退裸跑
[错误 tool/sandbox-failed] 沙箱初始化失败：Landlock NotEnforced（内核不支持）
提示：沙箱启用但内核不可强制时按安全策略拒绝执行；请检查内核版本（≥5.13）或将 [sandbox] enabled 显式置 false

# ③ 用户命令被内核拒绝：原样透传（模型与用户可见真实原因）
./build.sh: line 3: /etc/hosts: Permission denied   # EACCES 原样，退出码非零
curl: (7) Failed to connect                          # 网络禁断预期行为，错误透出
```

## 示例 5：模型告知段（section 注册文本，事实面四条）

```markdown
## 沙箱执行环境
你的 bash 命令在系统沙箱中执行。这是内核级硬边界，不是可协商的规则：
- **可写范围**：仅当前工作区目录。工作区之外的任何写入都会被拒绝——需要写工作区之外的位置时，停下来向用户说明诉求（目标路径与原因），由用户决定调整工作区或自行操作，不要尝试绕过。
- **无网络**：命令不能访问网络。`git clone`、`cargo add`、`pip install` 等需要下载的操作会失败，这是预期行为，不会因重试而改变；优先使用本地已有的依赖与仓库，确需联网时停下来告知用户。
- **权限拒绝≠故障**：看到 `Permission denied`、`Operation not permitted` 或命令异常退出时，先判断是否触碰了上述边界；若是边界拒绝，不要换写法反复重试（换 shell 语法、编码、间接调用都不会成功），直接改道或说明原因。
- 工作区内的常规开发动作（读写文件、构建、测试）不受影响。
```

注册纪律（诚实律）：仅沙箱实际生效时注册此段；`enabled=false` 或 enforcer 缺失时不注册；插件卸载段随 disposer 消失——验收三态断言=生效含段/降级无段/卸载段消失。
