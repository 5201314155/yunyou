# web.v1 域细则：team / tasks

> **状态**：**已冻结 v1.0（2026-11-19，lead 批）**。形状源：`yunyou-team` TeamService/board.rs/roster.rs 实测。
> 总则见 `规格.md`（权限分级 L1–L5、错误码）；执行链与命令缝见域-会话命令与技能.md。

## 1. team 域

### 1.1 名册（team/roster，L1）

`{items:[{name,description,online,busy,task?}]}`：

- `online` 真源=hub members()（fiber 存活），`busy`=成员回合循环置位，`task`=任务板投影合成；两表不重复记账，服务端合成后输出；
- 名册条目在成员 kick/离场后保留元数据（hub 降级保留语义同源），online=false 表离线；同名重拉续投复用条目、描述不覆盖。

### 1.2 拉人（team/spawn，L4，需显式授权）

payload `{name!, description!, prompt!, context:"fresh"|"fork"}` → `{name,description,note}`：

- `name` 全局唯一；重名任何态 fail-loud（`team/state` 或 hub 错误透传，details 含冲突名）；「Pending 在册=离线成员重拉」不视为冲突（续投语义）。
- `context=fresh`（默认）=空白上下文；`fork`=lead 对话摘要注入人设段（**一期降级形态**——前端如实说明「fork 摘要降级，非完整会话复制」，规范 §7.3）。
- spawn 返回=成员 Active+信箱就绪（await_ready 语义）；失败回收名字（信箱 dispose），不留半成品。
- fork 摘要数据源=lead 会话 JSONL 尾部压缩；成员会话文件=同目录 `teammate-<名>.jsonl`（config.path 同源派生，不新开配置键）。

### 1.3 成员消息（team/message，L2）

payload `{to!, body!, kind:"chat"|"report"?}` → `SentReceipt` 投影 `{to,accepted:true,logId}`：

- 身份=lead（服务端强制，不可自报发送者——身份收在 fiber 上下文，模型与调用方都无法伪造 from）；
- 寻址/缓冲/留痕全在 hub；成员离线=信箱续投（Pending 在册），响应仍 accepted；
- `to` 不在册 → `team/unknown-member`。

### 1.4 踢人（team/kick，L3，前端二次确认）

payload `{name!}` → `{kicked:true}`；dispose 成员 fiber（hub 条目降回 Pending、信箱保留），名册簿记同步清除。成员名不在册 → `team/unknown-member`。

## 2. tasks 域

### 2.1 状态机（board.rs 实测冻结）

```
pending → claimed → submitted → (reviewing) → approved | rejected
```

- `reviewing` 保留为观测态（v1 与裁决同点原子通过，不拆分审查领取 RPC）；
- rejected 为终态：重做=新建任务（不做「打回重开」RPC，v1 不留）；
- 依赖：`blocked_by` 前置任务 approved 后自动解锁并通知负责人（服务端行为，前端只展示阻塞来源）。

### 2.2 方法

| 方法 | payload | 响应 | 级 | 服务端强制校验 |
| --- | --- | --- | --- | --- |
| tasks/create | `{title!,description!,capability?,blocked_by?}` | `{taskId}` | L2 | 必填项 |
| tasks/claim | `{taskId!,owner?}` | `{claimed:true}` | L2 | owner 须在册；非 pending → `team/state` |
| tasks/submit | `{taskId!}` | `{submitted:true}` | L2 | 仅 owner（否则 `team/not-owner`，details 带 owner/actor） |
| tasks/review | `{taskId!,approve!}` | `{approved:bool}` | L3 | **审查人=提交人 → `team/self-review`，板层强制，lead 不可绕过** |
| tasks/reassign | `{taskId!,newOwner!}` | `{reassigned:true}` | L3 | newOwner 须在册 |
| tasks/list | `{}` | `{items:[{id,title,state,owner?,createdBy,submittedBy?,reviewer?,capability,blockedBy[]}]}` | L1 | — |

注：tasks/list 返回**全量投影**（TeamTask 全字段，比内部 task_list 工具的薄投影宽——Web 看板需要 created_by/submitted_by/reviewer/capability/blocked_by 渲染状态与自审锚点）；事件 `tasks/changed` 只作增量提示，前端收到后重拉 tasks/list（单真源，websocket.md §4.2）。

### 2.3 权限与防呆

1. Web 端操作者身份恒为 lead 视角：claim 可指定 owner（代派）；submit/review 的 actor=lead 或被点名的真实成员，`ensure_actor` 在册校验不过即 `team/unknown-member`。
2. 自审拒绝（SelfReview）错误 message 人话含三方（提交人/审查人/任务号），前端原样展示，不翻译成通用「操作失败」。
3. 面板纪律（写审分离的接口面映射）：review 是 L3，接口不拦已授权调用，但前端二次确认；「非负责人不代改完成态」由 owner/not-owner 校验承担。
