## 0. 契约地位与诚实标注纪律

1. 本文只定**接口契约**，不授权代码施工；实施批按设计规范 §十 B0–B5 分期。
2. 每个方法/端点带状态标注，三档，**禁止把「设计冻结」写成「已接」**（第七条铁律反超前声明）：
   - `[已接]`：yunyou-web 现有代码已实现，形状与本文一致；
   - `[冻结待接]`：本文冻结形状，实施批按此落码；
   - `[后续]`：列入产品范围但依赖未开闸缝（proto v1.1、S11 工作区授权、二期 market），本文只定占位语义与错误码，不给假形状。
3. 禁止假控件原则（规范 §2.4）：未接方法返回 `gateway/not-implemented`（fail-visible），前端不得渲染成功假象。

## 1. 传输面总览

| 通道 | 入口 | 用途 | 形态 |
| --- | --- | --- | --- |
| unary RPC | `POST /api` | 全部请求-响应方法 | `client-request`/`server-response` 信封 |
| mux 流 | `GET /api/remote.mux`（WS 升级） | 事件推流、快照重放、投影 | open/item/end/error JSON 文本帧 |
| 静态资产 | `/`、`/app.*`、`/tokens.js` | 页面与设计令牌生成物 | 不入契约（实现细节） |

**鉴权（三通道同规）**：token 恒开、无匿名通道。候选令牌取 `?token=`（启动打印 URL）> `Authorization: Bearer` > 会话 cookie `yunyou-web-token`（httpOnly+SameSite=Lax）；校验常量时比较。未鉴权=HTTP 401（WS 升级拒绝）。默认绑 `127.0.0.1`，非回环启动打印外泄提醒。

## 2. unary RPC 信封与统一错误形状

### 2.1 请求/响应信封（[已接]，rpc.rs 实测形状冻结）

```jsonc
// 请求体（POST /api）
{ "type": "client-request", "rpcId": "<客户端生成，响应原样回带>", "method": "<域>/<动作>", "payload": { "args": { ... } } }
// 响应体（HTTP 200，业务成败在 result 内）
{ "type": "server-response", "rpcId": "<原样>", "result": { "ok": true, "value": { ... } } }
// 失败
{ "type": "server-response", "rpcId": "<原样>", "result": { "ok": false, "error": { "code": "...", "message": "...", "details": {} } } }
```

- 信封形状错误（非 JSON / 非 client-request）：HTTP 400 + 同款错误体，`rpcId=null`。
- `payload.args.request` 单参方法惯例；兼容直接 payload 形态（无 args 包装）。
- 网络层 HTTP 状态只表达**信封级**失败（400=请求不可解析）；业务失败一律 200 + `ok:false`。

### 2.2 错误码词表（三字段统一：code/message/details，message 恒中文人话）

| code | 语义 | HTTP | 稳定级 |
| --- | --- | --- | --- |
| `gateway/bad-request` | 信封/参数形状非法 | 400 或 200 | v1 冻结 |
| `gateway/not-implemented` | 方法未接（fail-visible，不许伪造值） | 200 | v1 冻结 |
| `gateway/bad-frame` | mux 帧 JSON 非法 / 上行 type 不认识 | 流内 error 帧 | v1 冻结 |
| `session/agent-busy` | 回合闸门占用，新 prompt 拒绝 | 200 | v1 冻结 |
| `session/no-active-turn` | 无进行中回合，cancel 拒绝 | 200 | v1 冻结 |
| `session/prompt-invalid` | prompt 缺 requestId / mode 非 queue|steer / 正文空白 | 200 | v1 冻结 |
| `config/revision-conflict` | 修订号过期，配置已被别处更新 | 200 | v1 冻结 |
| `config/validation` | 配置段深度校验失败（details.keys 列非法键） | 200 | v1 冻结 |
| `credentials/write-only` | 试图读回 secret 明文（恒拒绝，见 §4） | 200 | v1 冻结 |
| `team/state` | 任务板状态机违例（details 含 from/op） | 200 | v1 冻结 |
| `team/not-owner` / `team/self-review` | 非本人操作 / 写审分离拒绝（板层强制，lead 不可绕过） | 200 | v1 冻结 |
| `team/unknown-member` | actor/owner 不在名册 | 200 | v1 冻结 |
| `schedule/spec` | 三选一必填恰一 / 间隔低于 5 分钟下限 | 200 | v1 冻结 |
| `schedule/unknown-id` | 删除不存在的调度（details.entries 列现有 id） | 200 | v1 冻结 |
| `plugin/restricted` | market 插件权限未开闸（network/credentials 恒禁期） | 200 | v1 冻结 |
| `plugin/ui-page-rejected` | manifest ui kind=page 二期预留，拒装（对齐 manifest 契约 §3） | 200 | v1 冻结 |
| `system/forbidden` | 远程管理动作越权（§5 权限边界） | 200 | v1 冻结 |

`details` 最小化原则：只放定位所需结构化字段（如 `{"keys":["llm.timeout_secs"]}`），**永不放 secret 值、永不放内核栈**。

## 3. revision 乐观锁（配置写入通用规）

1. 所有「读-改-写」型资源（settings 全段、插件 enable/config、凭据槽位、team 配置面）投影响应必带 `revision: integer`（单调递增，从 1 起）。
2. 写请求必带 `revision`；服务端比对：
   - 相等 → 写入成功，响应 `revision: 旧+1`；
   - 不等 → `config/revision-conflict`，`details: {"current": <n>}`，前端提示「配置已在别处更新」并提供重新加载（设计规范 §7.3）。
3. 同一进程内 revision 单源（config 层计数器），不承诺跨重启保留；重启后 revision 重置，前端以重启事件（websocket.md §4 `system/restarted`）作废缓存。
4. scheduler/任务板等**非配置资源**不用 revision：任务板用状态机原子迁移（每次操作即事务），定时任务用 id 定点删。

## 4. secret 只写不回显（红线，对齐 yunyou-credentials redact/settings）

1. schema 词汇：字段级 `role: "secret"`（schemars extend 平铺）是唯一声明方式；`llm.api_key` 已标注为既存事实。
2. 读投影（settings/表单/凭据目录）：
   - secret 字段**整字段移除**，sidecar 记 `{path, set}`（set=false 也枚举，供「未配置」态）；
   - 表单字段 `value` 与 `default` 对 secret **恒 null**，`required` 恒 false（plainSchema 语义）；
   - 凭据目录只显示：槽位路径、是否已配置、引用来源（如 `$YUNYOU_LLM_API_KEY`）、store 路径（如 `<yunyou-home>/credentials.toml`，600 权限）。
3. 写路径：写 secret 走专用写方法（域-配置凭据与插件.md），值只进托管存储或定点改写为引用；**任何读方法返回明文=契约违规**，测试须锁死（对齐 `credentials_段反序列化与缺省` 同级断言）。
4. secret 值不进日志、不进错误 details、不进事件流。

## 5. 远程管理动作权限边界

Web 端是**远程管理面**，动作分级；分级定了「谁可直接做、谁要二次确认、谁本期不开」：

| 级别 | 动作 | 规则 |
| --- | --- | --- |
| L1 只读 | 全部 list/get/follow/投影 | 直通；读不到=空值或 not-implemented，不伪造 |
| L2 会话动作 | prompt/cancel/命令执行/任务认领提交 | 直通；后果可见（回真实事件流，命令结果落会话） |
| L3 破坏性 | 任务 review 裁决、任务 reassign、踢人 kick、插件启停/删除、定时任务删除、凭据替换 | 接口不拦，**前端二次确认**；写审分离与 owner 校验在服务端强制 |
| L4 管理动作 | spawn_teammate、settings/凭据写入、插件安装、工作区根修改 | 契约面开放，但：spawn/安装/凭据写入须 lead 或用户侧显式授权语义（Web 一期=操作前用户点确认；后续接权限审批插件判定链 task-16） |
| L5 不开 | 跨重启 durable 定时（用户未明说即 false）、market 插件 network/credentials、热更新、插件工具取消 | 恒拒绝 `plugin/restricted` / durable 一律按会话内有效投影，不得显示跨重启开关（规范 §7.2） |

服务端强制项（不依赖前端自觉）：任务板 owner/self-review 校验、命令 D2 落盘配对、secret 零回显、`/quit` 不杀服务（断本连接）、回合闸门串行。

## 6. 事件增量与加法演进

1. **持久事件**（进快照重放环）：seq 全局致密 +1；surface 事件（user/assistant/system message、tool/result）必带 `surfaceOp:"append"`。词汇清单见 websocket.md §3。
2. **暂态帧**（不进重放）：assistantStream chunk 帧以 `revision` 逐帧 +1（跳号=客户端重连信号）、chunk `index` 致密 0,1,2…；end 帧 `committed.seq` 指向已推落定事件。
3. **加法演进纪律**：v1 冻结面内只允许——新增事件 type（消费端未知 type 必须可忽略不崩）、事件 data 内新增可选字段、新增方法/端点、新增错误码。禁止：改已有字段语义、删字段、改枚举已有值含义、改 seq/revision 铁律。破坏性变更发 `web.v2` 并保 v1 兼容期（对齐 manifest 契约 §7 版本化纪律）。
4. 快照缺失容忍：重放环 512 条封顶，超出丢最旧（完整流在会话 JSONL）；`session/page` 兜底翻页返回空页 `hasMore:false` 是诚实现态（历史全量回放属后续批，见 §8）。
5. 广播积压：服务端可丢 live 帧（客户端按 revision/seq 跳号自重连对齐），这是约定行为不是缺陷。

## 8. session 域方法（[已接]，形状冻结）

- `session/list` → `{items:[{sessionId,agentAvailable,updatedAt,running,blank,projections:{kind:"sequenced",asOfSeq,values}}]}`；未铸会话=空数组（诚实，不造假行）。
- `session/create` payload `{sessionId?}` → `{sessionId}`；铸造或复用。
- `session/prompt` payload `{requestId!, mode:"queue"|"steer", content:[{type:"text",text}]}` → `{accepted:true}`；校验链与错误码见 §2.2；受理后事件经 follow 流回流（requestId 必须出现在 user/message `source.rpcId`——乐观 echo 退场凭据）。
- `session/cancel` → `{accepted:true}`；无进行中回合=`session/no-active-turn`。
- `session/page` → `{records:[],hasMore:false}`（诚实空页）。
- `session/modelCatalog` → 单提供方诚实目录 `{default:{provider:"yunyou",model},routableProviders:["yunyou"],groups:[…],failures:[]}`；不虚构多提供方目录（规范 §2.3）。

## 9. commands / skills / capabilities 域

### 9.1 commands（[已接执行链，冻结目录投影]）

- `commands/list` → `{items:[{name,aliases[],description,kind:"action"|"expand",accepts_args}]}`，字典序稳定（BTreeMap）。来源=CommandsService 注册表；别名×别名冲突在注册时 fail-loud，投影内不出现冲突别名。
- `commands/execute` payload `{raw:"/命令 [参数]"}` → `{ok, text}`；语义与 web 壳命令缝同源：动作类不收参数（余段提示不阻断）、未知命令 ok=false、**展开类（技能）不代发**——返回原文并注明回填语义；`/quit` 由壳层拦截=断本连接（不杀服务，其他连接不受影响）。执行全程持回合闸门（与回合并发安全），run/done 配对落会话 JSONL。

### 9.2 skills（[冻结待接]）

- `skills/list` → `{items:[{id,name,description,source:"builtin"|"project"|"plugin"}]}`；来源即技能目录真实分层，不虚构。
- `skills/get` payload `{id}` → `{name,description,body}`；body=技能正文（前端展示，发送须走用户显式动作）。技能在本契约=命令展开类+目录读取，不是可执行 RPC。

### 9.3 capabilities（[冻结待接]）

- `capabilities/list` → `{items:[{key,title,description,available:boolean,gate?:string}]}`；投影来源：内置工具清单、manifest ui 条目、proto 工具清单、scheduler/team 等服务缝。`available=false` 必带 `gate`（如 `"proto.v1.1 未开闸"`），前端据此灰置并说明，不出假开关。

## 10. 全域时间与编码约定

- 时间戳：毫秒 epoch 整数（`now_ms` 语义），字段名 `*At` / `*_ms` 二选一按现有源码形状。
- id：uuid v4（会话/事件/attempt）或域内自增（任务板 u64）或业务串（调度 id）。
- 全部文档、错误 message、枚举说明用中文；技术标识符（方法名、错误 code、事件 type）用现有英文 kebab/slash 形态。

## 11. devices / system 域（[冻结待接]）

- `system/info` → `{version, contract:"web.v1", model, workspaceRoot, sessionDir, startedAt}`；关于页数据源（MIT、上游归属走静态资产，不入此接口）。
- `system/health` → `{ok:true, uptimeMs, turnOpen}`；探活面。
- `devices/current` → `{connected:boolean, via:"query"|"bearer"|"cookie", loopback:boolean}`；只描述**当前这条连接**的鉴权形态与安全面，不提供令牌读回（token=secret 红线同规）、不提供设备清单（多设备管理属后续，先不开）。
