## 1. session 域

### 1.1 多会话语义（实施堵点①，如实分级）

现状（[已接]）：单会话服务——WebState 只铸/持一个活跃会话，`session/list` 返回 0 或 1 行；`session/page` 诚实空页。契约按**多会话目标形状**冻结，实施批向此收敛，收敛前行为按现状标注：

1. 会话标识：`sessionId` 全局唯一（uuid v4）；未显式 create 前无会话（list 空数组、follow header.id="default"）。
2. `session/list` 目标形状（多行）：`{items:[{sessionId,agentAvailable,updatedAt,running,blank,projections:{kind:"sequenced",asOfSeq,values:{title?,sessionListMetadata}}}]}`；现态=单行或空，形状不变（加法兼容）。
3. 会话恢复（[已接]，v1.1 增量）：`session/open` payload `{sessionId}` → 切换活跃会话并回放其 JSONL 尾部进快照；响应含 `ingested/skipped/skippedNote`（回放审计面），快照可选字段 `skippedEvents`（加法演进，消费端缺失容忍）。前端不得用 create 冒充恢复。
4. 历史回放：完整历史在会话 JSONL（与 CLI 同纪律）；Web 重放环 512 尾部封顶，`session/page` 翻页属后续批（诚实空页），不得渲染假「加载更多」。
5. 会话间隔离：prompt/cancel/事件流都锚定活跃会话；**【裁决已定，lead 2026-11-19】follow 收敛为按 sessionId 路由**——快照与 live 事件均按 address.sessionId 定向，云络 W2 按此实施，UI 排期不受现态「只推活跃会话」限制。

### 1.2 回合与闸门

1. 回合闸门：一次一个回合；占住时 `session/prompt` → `session/agent-busy`（人话：「当前会话正在对话中，等本回合落定再发新消息」）。前端禁止在 agent-busy 时本地排队假装受理。
2. `mode` 只收 `queue|steer`（形状校验在先）；steer 的插话语义随 agent-loop 演进，v1 不承诺打断。
3. 取消：`session/cancel` → `{accepted:true}`；取消落款=事件流 system/message「已停止本回合（用户取消）」+ turn/end(error)。无回合=`session/no-active-turn`（fail-visible 不装成功）。
4. requestId 对账铁律：受理即登记，user/message `source.rpcId` 必带；这是乐观 echo 退场唯一凭据。

### 1.3 工具结果与审批卡

- tool/call `arguments` 为 120 字符摘要（现态）；工具详情展开需要全量时，read/edit/bash 结果在 tool/result `content`（canonical value 原样，字符串或结构化）。
- 审批卡（[冻结待接]）：本期无审批 RPC；权限审批插件（task-16）判定链开闸后以 `tool/call` 前置事件 `approval/request` 增量接入（加法演进），v1 不留假接口。

## 2. commands 域（实施堵点②：Action/Expand 二分）

### 2.1 目录投影

`commands/list` → `{items:[{name,aliases[],description,kind:"action"|"expand",accepts_args}]}`：

- 字典序稳定（BTreeMap）；别名不建索引，`find` 先精确名后别名遍历（精确名优先，别名不遮蔽任何精确名）；
- 注册期冲突 fail-loud（主名重复、别名×别名冲突），投影内不出现冲突条目；
- kind 二分是前端行为分派唯一依据。

### 2.2 执行语义（commands/execute，payload `{raw}`，raw 含前导斜杠）

| 情形 | 行为 | 响应 |
| --- | --- | --- |
| Action 成功、输出非空 | 执行并落 D2 配对（command-run → command-done） | `{ok:true,text}` |
| Action 成功、输出空 | 静默（REPL 同规） | `{ok:true,text:""}` |
| Action 收到参数余段、accepts_args=false | 不阻断，提示前缀「/{token} 未接受参数，已忽略：{余段}」 | `{ok:true,text}` |
| Expand（技能展开类） | **不代发**：返回原文+注记「回填文本：如需发送请自行编辑后发送——web 一期不代发」 | `{ok:true,text}` |
| 未知命令 | 「未知命令 /{token}（/help 看命令）」，**不落盘** | `{ok:false,text}` |
| commands 服务未就绪 | 人话错误 | Error 事件 |

1. 并发纪律：执行全程持回合闸门（与回合、与其他命令串行；/new 重建装配的安全前提）。
2. 落盘纪律：run 先于 handler、done 后于结算（/new 换槽则落新文件，配对键跨文件）；store 缺失/失败仅告警不阻断。
3. `/quit` 壳层拦截：断开本连接（bye 帧），不经命令缝、不杀服务。
4. 命令结算回真实会话（事件流 CommandOutput 帧 + JSONL 落盘），不能只弹本地菜单（规范 §2.3）。

## 3. skills 域

1. `skills/list` → `{items:[{id,name,description,source:"builtin"|"project"|"plugin"}]}`；来源分层是真实技能目录投影，禁止虚构来源。**【注记】source 三值中 builtin/plugin 层在 yunyou 现态无实料目录，v1 投影恒 `"project"`（诚实不虚构）；builtin/plugin 层落地后加法演进。**
2. `skills/get` payload `{id}` → `{name,description,body}`；body=技能正文。
3. 技能在本契约=**命令展开类 + 只读目录**，不是可执行 RPC；执行技能=用户把展开文本编辑后经 prompt 发送（与 Expand 不代发同规）。
4. 技能注册缝（manifest ui 条目）按 manifest-v1 契约 §3 落；`.dsh/skills/` 属宿主级机制，不在本契约面。
