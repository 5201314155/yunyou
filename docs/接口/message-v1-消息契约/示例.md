# message.v1 契约示例

> 配套 `规格.md`。示例为签名级骨架（T1 实现批前的教学形态），以权威设计 `docs/架构/MessageHub契约设计-任务26T1.md` 为准。

## 示例 1：团队插件的成员装配流（Rust 骨架）

```rust
// yunyou-team 插件（T2 卡）的 spawn_teammate 工具实现要点：
async fn spawn_teammate(hub: &dyn MessageHub, ctx: &Context, name: &str, prompt: &str) -> Result<()> {
    // ① 预注册信箱：spawn 窗口内发往该名字的消息落缓冲，不丢
    let mailbox = hub.open_mailbox(name)?;               // 重名/空白名在此 fail-loud
    // ② 拉起成员 fiber（独立 Session+AgentLoop）；失败路径 dispose 回收名字
    match spawn_member_fiber(ctx, name, prompt).await {
        Ok(fiber) => { std::mem::forget(mailbox); /* fiber 存续期=信箱存续期 */ Ok(()) }
        Err(e)    => { drop(mailbox); Err(e) }        // EffectHandle 提前 dispose=回收
    }
}

// 成员 fiber 的 setup 内（身份=该 fiber，后续 send/drain 均派发为此成员）：
fn member_setup(hub: &dyn MessageHub) -> Result<()> {
    hub.register(NAME)?;                                  // Pending→Online，补投就绪
    // 观测面订阅（可选）：入站镜像，尽力而为
    hub.subscribe(Arc::new(|msg: &DeliveredMessage| Box::pin(async move {
        log::info!("入站: {} → {:?}", msg.from, msg.kind);
        Ok(())
    })))?;
    Ok(())
}

// 成员循环每轮请求前（宿主机制，非模型工具）：取净信箱 → 注入 system 段
fn before_each_request(hub: &dyn MessageHub) -> Option<String> {
    let inbox = hub.drain().ok()?;                        // log_id 升序，含补投缓冲
    (!inbox.is_empty()).then(|| render_inbox_section(&inbox)) // 经契约③ section 缝注入
}
```

## 示例 2：send_message 工具（模型面）——无 from 参数

```rust
// 工具参数 schema：只有 to 与 message（模型无法自报发送者——hub 派发身份）
// { "type": "object", "required": ["to", "message"],
//   "properties": { "to": {"type": "string"}, "message": {"type": "string"} } }
fn execute_send_message(hub: &dyn MessageHub, to: &str, body: &str) -> ToolOutcome {
    match hub.send(&Address::Member(to.into()),
                   OutgoingMessage { kind: MessageKind::Text, body: body.into() }) {
        Ok(r) => ToolOutcome::ok(json!({ "log_id": r.log_id, "recipients": r.recipients,
                                         "buffered": r.buffered })),
        // typo / 未注册名：fail-loud 透出，模型据 hint 改道
        Err(e) => ToolOutcome::err_h("message/unknown-member", e.message(),
                                     "该名字未在册；用 members 查询在册名单后重发"),
    }
}
```

## 示例 4：错误响应两态

```jsonc
// ① typo 名（未预注册未上线）→ send 立即 Err（不静默吞）
HubUnknownMember: "消息目标 \"yun-w0\" 无任何在册或预注册条目"
// ② 越权读：非成员 fiber 调 drain → 立即 Err（防取净他人信箱）
HubUnknownMember: "当前 fiber 未注册为任何成员，无法取信箱"
// ③ 重名绑定：第二个 fiber register 同名 → 立即 Err（对齐 ServiceDuplicate 报错格式）
HubDuplicateMember: "成员 \"yun-wo\" 已由 <yun-wo fiber> 绑定"
```

## 示例 5：完工自动汇报（Report 机制语义）

```rust
// 成员 fiber 内的收尾钩子：run_turn 终结（Ok/Err/取消）时由成员 fiber 自身发送
// ——谁终结谁发送；在 lead fiber 代发会被身份派发拦截（规格 §5 规则 4）。
async fn report_completion(hub: &dyn MessageHub, summary: String) -> Result<()> {
    hub.send(&Address::Member("lead".into()),
             OutgoingMessage { kind: MessageKind::Report, body: summary })?;
    Ok(())
}
```
