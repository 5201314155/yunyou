## 1. 定位与消费方

三职责：**注册成员 / 寻址投递 / 留痕**（任务26 台账原文：消息池=发布订阅+寻址+留痕，面板插话/成员互联/AI 自提醒同一管道）。第一个客户端=yunyou-team 团队插件；**缝在内核卡在插件**——hub 由内核 root 装配 provide，团队卡禁用不杀缝（后续消费方不依赖 team 在位）。

与事件总线的边界：scoped events（`emit_owned`/`on_owned`）是事件面（归属通知），不承载寻址投递与留痕——「零新机制的检验口径=检验机制而非数据结构」（lead 批为设计律级表述），论证见权威设计 §2。

## 2. 服务 trait（七方法，全同步）

```rust
/// 契约 message.v1：进程内消息枢纽（发布订阅 + 寻址 + 留痕 + 信箱补投）。
pub trait MessageHub: Send + Sync + 'static {
    /// 预注册信箱（Pending 态）：spawn 拉起窗口的消息落点。
    /// EffectHandle 挂调用 fiber——spawn 失败可提前 dispose 回收名字；
    /// 重名（任何态）/空白名 fail-loud。
    fn open_mailbox(&self, name: &str) -> Result<EffectHandle>;

    /// 成员上线：绑定当前 fiber。Pending→Online（补投就绪）；无条目→直接
    /// Online（自发成员，如 lead）；已 Online→HubDuplicateMember。
    /// EffectHandle 语义：fiber 死亡→条目降回 Pending（信箱与未取净消息保留）。
    fn register(&self, name: &str) -> Result<EffectHandle>;

    /// 名册消息侧投影（online 标志+归属；Pending 无归属=spawn 窗口可见性）。
    fn members(&self) -> Vec<MemberInfo>;

    /// 观测面订阅（推，尽力而为）：当前 fiber 绑定成员的入站镜像；
    /// handler 失败记日志不上抛（消费保证在 drain）。
    fn subscribe(&self, handler: MessageHandler) -> Result<EffectHandle>;

    /// 寻址投递：身份由 hub 按调用 fiber 派发（防伪造）；Online=入信箱
    /// +观测镜像，Pending=信箱缓冲，未在册=HubUnknownMember。
    fn send(&self, to: Address, message: OutgoingMessage) -> Result<SentReceipt>;

    /// 消费通道（拉）：取净当前 fiber 绑定成员的信箱（log_id 升序）；
    /// 非成员 fiber=HubUnknownMember。
    fn drain(&self) -> Result<Vec<DeliveredMessage>>;

    /// 留痕查询：环形 1000 丢最旧；完整历史=各成员会话 JSONL（会话域）。
    fn history(&self, query: HistoryQuery) -> Result<Vec<HistoryEntry>>;
}
```

## 3. 数据形态

```rust
pub enum Address { All, Member(String) }
// All=在册全体（含 Pending，缓冲），不含 from 自己；**保留广播地址**：
// 成员名 "all" 注册即拒（task-30，send_message to=all 大小写不敏感广播全体，
// 注册拦截防跨成员误投）；**零成员广播 fail-loud**（除 from 外零在册=人话
// Err，原「空集照样 Ok」口径 2026-11-17 由 task-30 翻转废止）。
pub enum MessageKind { Text, System, Report }     // 三值冻结；Report=完工自动汇报机制语义
pub struct OutgoingMessage { pub kind: MessageKind, pub body: String }
pub struct MemberInfo { pub name: String, pub online: bool, pub fiber: Option<EventOwner> }
pub struct DeliveredMessage { pub log_id: u64, pub from: String,
    pub kind: MessageKind, pub body: String }     // 收件面不暴露 to=最小知识面
pub type MessageHandler =
    Arc<dyn Fn(&DeliveredMessage) -> BoxFut<'static, Result<()>> + Send + Sync>;
pub struct SentReceipt { pub log_id: u64, pub recipients: usize, pub buffered: usize }
pub struct HistoryQuery { pub limit: usize }
pub enum DeliveryStatus { Delivered, Buffered }   // 真账区分即时送达与缓冲补投
pub struct HistoryEntry { pub log_id: u64, pub at_ms: u64, pub from: String,
    pub to: String /* "All" 或成员名 */, pub kind: MessageKind, pub body: String,
    pub outcomes: Vec<(String, DeliveryStatus)> }
```

serde 纪律：全类型 derive `Serialize/Deserialize` + `serde(default)`/`skip_serializing_if`（双向兼容；二期 IPC schema 种子）。

## 4. 错误形态（fail-loud）

| 方法 | 失败 | 错误形态（`ErrorKind`） | 消费方动作 |
| --- | --- | --- | --- |
| open_mailbox | 同名在任何态 / 空白名 | `HubDuplicateMember` / `HubInvalidName` | 立即 Err；不静默改名 |
| register | 已 Online（本 fiber 或他人） | `HubDuplicateMember` | 立即 Err——重名绑定=路由欺骗 |
| send / drain | 调用 fiber 未绑定成员 | `HubUnknownMember` | 立即 Err——**防伪造机制化**：无身份者发不出、取不到他人信箱 |
| send | to 名无任何条目（未预注册且未上线） | `HubUnknownMember` | 立即 Err；typo 不静默吞 |
| history | 存储异常 | `Internal` 兜底 | 出现即内核缺陷 |

fail-loud 三不：不静默降级／不吞错／不假报成功（send 返回 Ok 当且仅当全部目标受理入箱/入缓冲）。`HubUnknownMember`/`HubDuplicateMember`/`HubInvalidName` 为 `ErrorKind` 新增变体（加法演进；全库无 match ErrorKind 穷尽点，2026-11-14 实测）。

## 5. 关键语义（五条硬规则，插件作者必读）

1. **身份派发防伪造**：send/drain 不接受名字参数，hub 按调用 fiber 从成员表派发身份——模型自报无效（send_message 工具无 from 参数），插件实现也无法伪造。发送/消费必须在成员 fiber 上下文内。
2. **信箱状态机** `Pending⇄Online`：send 到非 Online 在册名=缓冲（回执计 `buffered`，观测镜像照发、状态标 buffered）；**注册后首次 drain 即得全部缓冲**（=云伍「注册时补投」的等价落法）；fiber 死亡降回 Pending，同名重注册续投。
3. **双通道**：drain=消费通道，**宿主机制非模型工具**（AgentLoop 每轮请求前取净注入 system 段，经契约③ section 缝，模型无感）；subscribe=观测面（尽力而为，失败不上抛）。
4. **Report 发送点=成员 fiber 上下文**：完工自动汇报由成员 fiber 自身在 run_turn 终结时发送（谁终结谁发送）；在别处代发会被身份派发拦截——集成测试应锁定该行为。
5. **锁与观测**：send/drain 为同步短临界区（锁内快照、锁外派发，锁内绝不 await）；观测镜像=进程总线事件 `message.v1/watch`（尽力而为），payload 六位 `[log_id, from, to, kind, body, 状态]`。

## 6. 冻结面与留位（摘要）

- **冻结十项**：trait 七方法签名／MemberInfo／Address／MessageKind 三值／OutgoingMessage／DeliveredMessage／留痕面（含 DeliveryStatus）／错误形态／观测键 `message.v1/watch` 六位序／留痕机制语义（有界环形丢最旧+完整历史在会话域）。
- **留位八项**（触发条件见权威设计 §4.2）：持久化留痕／第四种 kind／收件过滤器／优先级插队／回执分级 ack／代发委托（on-behalf-of）／组播频道／跨进程传输与稳定 id。
- 版本化纪律：破坏性变更（改签名/删字段/收紧语义）发 v2 保留 v1 兼容期，manifest `contracts` 声明兼容区间；版本不符拒装不静默降级。
